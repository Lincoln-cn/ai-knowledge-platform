# mock 返回形状「跳过」的基线（`frontend/check_mock_endpoints.py` 第三维读它）
#
# 读法：`跳过 N` 是权威数字；下面每行 `文件 | 方法 | 路径 | 原因` 是当前跳过清单，
# 用来在数字变大时指认「新增了哪一处」（行号不参与比对 —— 改上面的代码会让行号整体平移，
# 按行号比对会把整份清单变成假新增）。改基线只能从脚本自己的 `--dump-skips` 输出里照抄，别手写。
#
# ★ 三条规矩（少了任何一条，这个文件就只是在给闸门自己签字）：
#   ① 这个数**只能减，不能悄悄增**。跳过 = 解析不出 / 无从比对，闸门对它不报红 ——
#      于是「闸门没管到」和「闸门管住了」读数一模一样，这个数就是唯一看得出区别的地方。
#   ② 跳过数**减少之后要把基线改小**（清单必须随修复收缩）。脚本只会提示
#      「基线可以降到 N 了」，绝不自动写文件 —— 自动改基线等于让闸门自己给自己签字。
#   ③ **新增跳过必须先说清「为什么解析不了」，不许只把数字调大。** 说不清理由，
#      就去修解析器（`_MockShaper._infer` 那一层），让这一处能判。
#

# ── 上面 41 条各自的理由，按原因归类 ──
# · 返回表达式解析不出 23 条：`return helper(...)` 的 helper 读了 handler 的形参
#   （`withOwnerName(app)` / `withApp(conv)` / `findKb(path.id, token)`），或 `return item`
#   这种循环里重新赋值的变量 —— 解析器只做同文件/夹具内的名字解析，不追形参流转。
# · 判不了（mock 对象带展开/动态键）9 条：`{ ...x, [key]: v }` 无法证明契约必填键在不在。
# · 判不了（多分支联合）4 条：守卫收窄后各分支形状不同，缺键不能作证。
# · 契约里同一路径有多个返回类型 4 条：契约自己没说死，无从比对。
# · 契约里没有这条端点 1 条：`/conversations/chat` 是第一维登记过的 SSE 例外。
