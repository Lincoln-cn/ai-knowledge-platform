## 二、判据：企业级 RAG 与单机 harness agent 的差别

**不在模型能力，在四件事** —— 权限粒度 · 留痕与留存 · 资源与成本上限 · 数据边界（`ROADMAP §11.3.1` 同一判据）。

★ 本项目在**第一件（权限粒度）上做得很扎实**（密级 pre-filter 两路同谓词 · `ScopeFilter` · grants · 组织三消费位），
**短板集中在另外三件**，以及对标中暴露的**第五件**：

| 判据 | 本项目状态 |
|---|---|
| 权限粒度 | ★ 扎实（但**权限的"来源"缺一环**，见 §四-1、§四-2） |
| 留痕与留存 | 审计**能力**已设计（`13 §七`，参照等保 2.0），**留存期与检索入口**没有口径 |
| 资源与成本上限 | ★ 基本空白（零指标零告警零配额，`#73`） |
| 数据边界 | ★ 基本空白（无出站闸门 `#72`、无 PII 脱敏） |
| ★ **知识主权（进得来）** | ★★ **对标中最大的缺口**：企业知识不在"手动上传"里，在**既有系统**里（见 §四-1） |

## 四、★ 真缺失逐条（用户未提到、设计里也没有）

按"现在不做以后是否返工"排序。「返工」一栏决定它是**留缝**还是**只记账**（判据见 `ROADMAP §11.7.1`）。

| # | 缺口 | 为什么企业级绕不开 | 现在不做的后果 | 建议 |
|---|---|---|---|---|
| 1 | ★★ **数据源连接器 + 增量同步 + ACL 同步** | 企业知识在 SharePoint / Confluence / 网盘 / 共享目录 / 企业 IM 里，**不在"事后手动上传"里**。AWS 把连接器与文档级 ACL 当作托管 KB 的**并列首要能力** | ★ 权限模型会变成**空中楼阁**：平台里的密级/组织是"平台内标注"，与源系统权限是两套；等做连接器时**每一条导入路径都要重新想权限** | **现在定一节口径**（`13` 增补：源系统权限如何映射到平台密级/组织；导入即带入）—— 见 §五 |
| 2 | ★★ **AD / LDAP / SCIM 目录同步** | 企业账号与组织从目录来；本项目的**数据权限就建在组织/部门上**（三消费位 + `#55`） | 组织树只能手工维护 ⇒ 必然与真实组织脱节，而脱节的组织树是**权限错判**的直接来源 | **现在定口径**（谁是组织的权威源；手工维护与同步的关系）+ 一条断言 |
| 3 | ★★ **合规要件**：备案/安全评估 · 深度合成标识 · 投诉举报入口 · 服务协议与适用人群 | 这四条是**法条明文**（第 12/15/17/9/10 条），不是"最佳实践" | 面向公众提供服务时**是准入问题**；事后补要动前端外壳、内容出口与管理后台 | **只记账 + `06` 补版本与判据**（不进 MVP：MVP 是内网试用，不向公众提供） |
| 4 | ★ **间接提示注入**（知识库内容本身是攻击面） | 企业 RAG 的注入面主要是**知识库里的文档**（被污染、被篡改、外部抓取来的）。`13 §12` 现在只防用户输入 | 一个被污染的文档可以让所有引用它的问答被操纵，**且引用看起来完全合法** | **现在在 `13 §12` 留一节 + 一条断言**（"检索回来的内容不被当作指令"的判定口径） |
| 5 | ★ **PII 检测与出站脱敏** | 数据出境/出站闸门（`#72`）管"发给谁"，**PII 脱敏管"发出去的是什么"** | 接外部模型时才发现正文里全是身份证/手机号，而**已经发出去过了** | **与 `#72` 同批留缝**（在出站链路上留一个可插的预处理点 + 断言"当前不脱敏"） |
| 6 | **文档版本与内容更新传播** | 企业文档会迭代；答案是"文档快照的证据" | 源文档已更新而平台仍答旧内容，且**引用看起来是权威的**（比"没有答案"更危险） | 记账（`0.5.x`）；现在只在 `02` 留一个"文档版本"字段的位置 |
| 7 | **答案忠实度读数**（faithfulness，与 B3 引用准确率**不同**） | B3 高只说明"引用对得上"，**不说明结论由引用支持** | 会出现"引用准确率 90% 而答案仍有编造"的组合，且**没有任何读数能发现它** | 在 `10`/`13` 的指标清单**加一格定义**（不要求 MVP 实现），第 18 周验收时人工抽查 20 条即可 |
| 8 | **噪声敏感度** | 多塞无关段落是否污染答案 —— 直接对应"分段窗口"（`#65`）与上下文预算的取舍 | `#65` 的滑动窗口会**增加**进入上下文的段落数 ⇒ 无此读数时无法判断"窗口开大是否反而变差" | 与 `#65` **同批**（它的判据里加一条"噪声敏感"的人工对照） |
| 9 | **灰度 / 对照实验** | 换 prompt、换模型、调阈值都需要"改前改后"的对照；Langfuse 视为标准能力 | 每次调整只能**全量上线后看总体指标**，无法归因 | 记账（`0.5.x`）；现在只在 `analytics` 留"按配置版本分组"的维度 |
| 10 | **PII/审计侧的管理员提权可审计** | Azure 设 elevated read 就是为了"管理员的越权查看也要留痕" | 审计表的两处真相风险（`13:763` 自己记了）+ 无留存期 ⇒ 审计在真实审计场合**说不清** | 并入 `#75` 的审计侧（留存期 + 按人/按资源入口） |

## 五、★ 看似缺、其实已有（**写下来是为了不重复记账**）

对标最容易犯的错是"把别人的能力当自己的缺口"。以下五项**本项目已有决策**，本次核对后**不记缺口**：

| 项 | 已有决策 | 触发条件（都在册子里） |
|---|---|---|
| **重排 cross-encoder** | `10 §4.5`"MVP 不做，补两个零成本替代" | `10:747` 路径 ① **B1 达标但 B3 不达标** ⇒ 召回够、排序不对时上 |
| **检索缓存 / 语义缓存** | `10:722,749` V1；`11:149` 首选官方 `SemanticCacheAdvisor` | 出现**重复提问热点**（看 `analytics` 查询去重率） |
| **审计** | `13 §七`（参照等保 2.0：覆盖到用户、可追溯、防篡改；日志表密级 ≥ 被审计数据） | 已设计，MVP 建表时留字段 |
| **无引用判定与拒答** | `10 §5`（A/B/C 三情形 + 固定话术） | 已设计 |
| **固定回归集** | `10:573` 50 个标注问题作为回归集 | 已定，缺的是自动化跑批 |

★ 还有一类**不算缺口但要记住**：`04` 的"明确不做"清单（审批流引擎 / 手机端 / 短信报表代码生成 / 手机号社交 SSO）——
它们是被**主动拒绝**的，不是遗漏。

## 六、结论

1. **功能面的最大缺口是"进得来"**（§四-1/2）：连接器、增量同步、ACL 同步、目录同步。四项都指向同一件事 ——
   ★ **本项目的权限模型是"平台内自足"的，而企业级要求它"跟着源系统走"**。这不是加功能，是**权限的权威源**问题。
2. **合规四件套（§四-3）是内网 MVP 之后的第一道门槛**：MVP 不面向公众提供，故不进 MVP；但一旦对外，它是**准入项**而非改进项。
3. **安全侧有两个真空缺**：间接注入（知识库内容）与 PII 出站脱敏（§四-4/5）—— 两者都**便宜地留缝**、昂贵地后补。
4. **评测侧缺"答案对不对"的读数**（faithfulness / noise sensitivity，§四-7/8），而现有 B1/B3 都是"检索对不对"的读数。
   ★ 这与 `#71`（OCR 准确度）是同一个病：**结果指标不达标时无法归因**。
5. **不需要记的**：重排、检索缓存、审计、拒答、回归集（§五）—— 已有决策，触发条件都写在册子里。

> ★ **一句话**：本项目在"**答得准**"上做得深（策略层成册、预算与降级、密级隔离），
> 缺口集中在"**进得来**"（知识主权）与"**管得住的后半段**"（合规、脱敏、留存、成本、评测归因）。
