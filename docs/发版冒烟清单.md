# 发版冒烟清单

> **这份文件解决什么问题**：`0.9.x` 这几版的共同形态是「单测绿、真栈待补」——
> 单测证明函数对不对，证明不了"服务起来后这条路走不走得通"。
> 每次发版前按下面顺序跑一遍，每条都给出**可核对的期望读数**；
> 读不出来就是这条路在真栈上坏了，不要用"单测是绿的"代替。
>
> 记录结果的地方是 [`验收台账.md`](验收台账.md)，那里是读数，这里是步骤。

## 一条命令跑完（推荐）

```bash
python scripts/smoke_check.py
```

它按下面 10 条逐项断言，输出 `[n] PASS/FAIL 名称 —— 读数`，最后给 `N / 11 通过`。
会真的建会话、真上传附件、真建公开链接与临时应用，**跑完自己清理**；
问答类条目会把「默认对话模型」临时切到桩模型（按 `baseModel = stub-plain` 找，
找不到就跳过而不是猜 id），跑完切回原值 —— 不许拿真实上游做冒烟。

**2026-11-20 实测：11 / 11 通过**（`firstTokenLatencyP50` 当时仍是 `null`，
因为 V113 还没执行 —— 第 1 条会把这个差值报出来）。

下面是手工版的步骤与判据，脚本坏了或要逐条核对时用。

## 0. 前置：服务确实起来了

| 检查 | 怎么做 | 期望 |
|---|---|---|
| 前端真栈 | `curl -o /dev/null -w "%{http_code}" http://localhost:5280/` | `200` |
| 后端 | `curl -o /dev/null -w "%{http_code}" http://127.0.0.1:18088/actuator/health` | `200` |

★ 两个坑：
- 前端只绑 `::1`，`http://127.0.0.1:5280/` 恒为 `000`，**必须用 `localhost`**。
- 后端启动的头十几秒 health 会返回 `503`，那是启动中，不是故障。
- `8080` 是 **JAiRouter**，不是平台后端。平台后端在 `18088`（见 `frontend/.env.development` 的 `VITE_API_TARGET`）。

## 1. 迁移到位

```sql
-- docker exec -i aip-postgres psql -U aiplatform -d aiplatform
select version, success from flyway_schema_history order by installed_rank desc limit 3;
```

期望：最新一条 `success = t`，且 `version` 与本版新增的迁移号一致。
**失败意味着**：新表/新列不存在，后面所有涉及它的读数都会假绿（接口 200 但字段恒 null）。

## 2. 登录与角色

| 账号 | 角色 | 用来验什么 |
|---|---|---|
| `admin / admin` | 管理员 | 全部功能 |
| `chenjun / 123456` | 普通用户 | 权限拒绝（第 7 条） |

```bash
curl -s -X POST http://127.0.0.1:18088/api/v1/auth/login \

```

期望：`{"code":200,"data":{"accessToken":"..."}}`。token 在 `data.accessToken`，不在顶层。

## 3. 通用问答跑通一轮（含开场白）

打开 `#/conversation`：

| 看什么 | 期望 |
|---|---|
| 第一条消息 | 有一条 `开场白`（不是空白页），正文三句 |
| 下方提示 | `试试这样问` + 4 条问法示例（总结 / 比较 / 判断 / 解释） |
| 工具条 | 只有 `附件` 与 `重排`，**没有**「提示词」按钮（它已在 0.9.4 撤掉） |
| 发一句 | 有流式输出，且回答下方有 `引用资料 N 条` 或 `本轮无引用` + 一行原因 |

**失败意味着**：`ensurePrologue` 与聊天链路任一环断了。零引用但没有原因行 = `notice` 通道没接上。

## 4. 附件真的参与问答

1. 上传一个含**世界上不存在**的字符串的文件（例：`内部代号：蓝鲸-8842`）。
2. 问「内部代号是什么？」
3. 看引用块与回答。

| 看什么 | 期望 |
|---|---|
| 回答 | 出现 `蓝鲸-8842` |
| 引用 | `kbName` 是 `会话附件`，且 `kbId` 为 `null`（会话域的判据） |
| 通用问答设置里召回**未启用**时 | 上面两条**仍然成立**（附件豁免开关） |

**失败意味着**：三种可能 —— 解析失败（文档 `status = SEGMENT_FAILED`）、阈值把它滤掉、或豁免没生效。查：
```sql
select name, status, segment_count, fail_reason from kb_document where kb_id is null order by created_at desc limit 5;
```
`SEGMENT_FAILED` 的行会带原因（例：`该内容 501 字，超出当前向量模型上限 500 字。`）。

## 5. 公开链接闭环（生成 → 访客提问 → 撤销失效）

```bash
# ① 生成
curl -s -X POST "$API/assistants/$APP/credentials" -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"expiresAt":null}'
# ② 访客读上下文（不带 JWT）
curl -s "$API/public/$CRED" -H "X-Access-Credential: $CRED"
# ③ 访客提问（★ 不是 /public/{token}/messages，那条会 405）
curl -s -X POST "$API/conversations/chat" -H "X-Access-Credential: $CRED" \
  -H 'Content-Type: application/json' -d '{"question":"你好"}'
# ④ 撤销，再重复 ③
curl -s -X POST "$API/assistants/$APP/credentials/$ID/revoke" -H "Authorization: Bearer $TOKEN"
```

| 步骤 | 期望 |
|---|---|
| ① | `200`，返回 `token` 与 `enabled: true` |
| ② ③ | `200`，③ 的 SSE 帧里有 `refs` 与 `text` |
| ④ 之后再 ③ | `404`，body `{"code":40402,"message":"访问凭证已撤销"}` |

## 6. 看板读数不是全空

打开 `#/analytics`：

| 看什么 | 期望 |
|---|---|
| 来源三态 | `全部来源 / 通用问答 / 应用`，默认「全部来源」 |
| 排行表 | 有 `调用数 · 会话数 · 轮/会话 · Token · 满意度` 五列 |
| 首字延迟（中位） | 跑过一轮问答后**应显示具体毫秒**，不是 `—` |

**失败意味着**：`first_token_ms` 没有落库（第 4 条里问过一轮就有了）。`—` 与 `0 ms` 是两回事：`—` 是"没有采样"，`0` 是"你测出来是零"。

## 7. 权限在接口侧被拒（不只是按钮藏起来）

用普通用户 token 调管理面：

```bash
curl -s -o /dev/null -w "%{http_code}\n" "$API/models" -H "Authorization: Bearer $USER_TOKEN"
```

| 端点 | 期望 |
|---|---|
| `GET /models` `/model-providers` `/roles` | `403` |
| `PUT /chat-settings`（**完整 body**） | `403` |
| `PUT /retrieval/settings`（**完整 body**） | `403` |

★ **必须用完整 body**：空 `{}` 会先被参数校验拦成 `400`，那个 400 不能证明权限生效（校验在鉴权之前跑）。

## 8. 提示词：改坏了能退回去

打开 `#/assistants/prompts`：

1. 改一条角色指令的正文 → 保存 → 点「历史」。
2. 期望：出现 `v1`（改之前那一版），diff 区显示 `− 旧句 / + 新句`。
3. 点「回滚到 v1」→ 期望：版本数变成 3（v1/v2/v3 **都在**），当前正文回到旧版。

**失败意味着**：`as_prompt_config_version` 没有写入（`snapIfChanged` 判定逻辑错），或回滚走了"删历史"而不是"生成新版本"。

## 9. 模板能建出应用

打开 `#/templates`：

| 看什么 | 期望 |
|---|---|
| 卡片数 | 11 |
| 点「从模板建应用」→ 确定 | toast `已建出新应用`，跳到 `#/assistants?focus=<新 id>` 并高亮 |
| 新应用的模型 | 自动补成本机一个**已加载**的对话模型（不是空） |

**失败意味着**：`multiTurn` 形状（`boolean` vs `object`）又写错了，或补位模型没生效。查：
```sql
select name, jsonb_typeof(payload->'config'->'multiTurn') from as_template where deleted_at is null;
```
期望全是 `boolean`。

## 10. 模型健康探测

打开 `#/models` → 「添加模型」：

| 看什么 | 期望 |
|---|---|
| 目录列表 | 每个模型带健康状态；不健康的卡片是**虚线红边 + 「不健康」tag**且不可选 |
| 点不健康的卡片 | 弹出原因（例：`上游返回 503：adapter ... is not resolved`） |
| 手动填一个不存在的模型再保存 | 被拒绝，提示「基础模型「X」当前不健康：…」 |

★ 这条只对 CHAT / EMBEDDING 生效；多模态（TTS/STT/IMAGE）不做调用探测，标为「未知」。
