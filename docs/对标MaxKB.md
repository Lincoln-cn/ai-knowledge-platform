## 一、判据：这篇文章在讲什么，我们在讲什么

文章把 MaxKB 的能力分成三档：

1. **RAG 知识库问答**（文档导入 → 分段 → 向量化 → 检索 → 带引用回答）
2. **工作流**（内置引擎 + 函数库 + MCP 工具调用 + 多路召回 + 判断器 + 多模态节点 + 分支/循环）
3. **智能体**（简易 = 按意图调工具；高级 = 工作流本身）

这套分层与我们 `ROADMAP` 的三档**同构**，所以对照是"同一件事的两种完成度"，不是"两个不同产品"。

★ **本文的判据只有一条：能不能用。** 界面上有按钮不算，端点返回 200 不算，
只有"用户点一下、它真的产生那个后果"才算。这条判据来自本项目自己的 `§11.6` 收尾第 ⑤ 条。

## 三、我们更强的三处（每条都有可核对物）

### 3.1 数据边界的深度

MaxKB 文章里权限只有一句「还能按团队划权限」。我们是**三层叠加**：

| 层 | 位置 | 关键判据 |
|---|---|---|
| 密级（四级） | 64 处引用；`13-密级与数据隔离设计.md` | **检索前置过滤**，不是查完再裁 —— 判据是"越权段根本不进候选池" |
| 组织树 | `ScopeFilter` 第 6 分量（40 处） | 归属精确、共享含下级、身份只放不可变字段（`code` 可进前缀，`name`/`path` 不行） |
| 权限点 | `PermissionCatalog` 21 个 | 后端 `@PreAuthorize` 与前端 `meta.permission` 同源 |

★ 判别方法：**"能不能做这个动作"与"能看到哪些"必须由两个模型分别回答**（本项目 `Architecture decisions` 的既有口径）。
只有一个答案的模型，必然用"隐藏按钮"冒充"限制数据"。

### 3.2 检索链路是真工程化过的

- **三模式**（FULLTEXT / VECTOR / HYBRID）+ **RRF 融合**（`retrieval/domain/Rrf.java`）
- **多跳迭代**（`#283`）：首轮命中不足时用 `MultiHopService` 再检一轮，四条 break 条件，全部失败路径"用已有结果继续"
- **21 条真缺口逐条取证**（`§11.10.92`）：答案句 20/21 在库、每条都有 10 条结果、最高分多为 1.000 ⇒ 不是召回不到，是排不进前 10
- **融合反例被实测抓到**（`#293`）：RRF 会把全文第 1 按到融合第 11；`§11.10.94` 记录了完整读数与那次"B1 +2 / B3 −3"的交换

MaxKB 文章这一档只有一句"把问题和库里最相似的段落拼成提示词"。

## 五、★ 落地建议：三批，按"缺了会怎样"排

### 第一批（决定性，不是可选项）

**执行引擎（`#113`）+ SSO（`#82`）**。

理由不是"MaxKB 有"，而是：

- 执行引擎决定**产品形态**：没有它，我们的"编排"永远停在"能画能存能发布"，第二档第三档能力全部悬空。
  `#113` 已经把它写成了"设计在册、无处验收"，再拖下去，将来接真引擎的成本会从"只换后者"变成"改整条链"
  （`09 §5.3` 提前写两段式的唯一目的就是防这个）。
- SSO 决定**能不能进政企**：RBAC 我们有（`identity` 模块 21 个权限点），但"人怎么进来"只有用户名密码。
  MaxKB 把 SSO 放在 4.8 万的专业版里 —— 说明这是**采购门槛级**的能力，不是加分项。

### 第二批（补形态，一周内能起量）

**工具调用留缝（G2）+ 触发器留缝（G5）+ 模板中心记账（G4）**。

这三条的共同点：**现在不做会返工**（`§11.7.1` 判据②）。
`NodeExecutor` 注册表落在哪个模块、`as_assistant` 要不要留 `trigger_*` 字段 —— 这些是**决定数据模型**的决定，
晚定就要改已经写好的路径。而"实现"全部可以排到 `0.5.x` 之后。

### 第三批（只记账，不排期）

函数库沙箱（G3）· 长期记忆（G6）· Excel（G10）· 网页抓取（G9）· 多模态（G8）。

它们**不满足** `§11.7.1` 的两条判据（`§二` 清单里没位置、现在不做也不返工）⇒ 记账即可。

## 六、结论

1. **我们赢在"管得住"，输在"用得上"。**
   数据边界（密级 + 组织 + 权限点）、审计、质量读数这三块比 MaxKB 深；但工作流不能跑、没工具、没模板、没 SSO。

2. **一个反直觉的分布**：文章说"免费版就够绝大多数场景"的那批能力 ——
   模板、MCP、多模态、长期记忆 —— **恰好是我们最空的**；
   而它放在 **4.8 万专业版**里的东西（完整 RBAC、SSO、共享资源管理），**RBAC 我们已有，差的只有 SSO**。

3. **不要追着 feature list 补页面。** 我们缺的不是"更多页面"，是**一条能跑通的编排链路**。
   在那之前，再多的页面都只是"壳"。

4. ★ **本文与 `docs/企业级RAG能力对标.md` 的分工**：
   那一份管"AWS / Azure / RAGAS / Langfuse / 中国法规"给出的**企业级判据**；
   这一份管"一个具体开源产品的**能力面**"。**两者重叠的部分（`#81`/`#82`/`#83`/`#84`/`#85`/`#87`/`#88`）以那一份为准，本文只引不重记。**
