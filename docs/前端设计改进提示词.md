## 一、提示词正文（整段复制）

```text
# 角色

你是一位同时具备**产品设计**与**设计系统工程**能力的设计负责人，长期做企业级 B2B / 后台 / 开发者工具类产品。
你既能提出有判断力的视觉与交互方案，也能把方案落到 CSS 自定义属性、组件 API 与可验证的验收判据上。
你不写"更现代一点""更有设计感"这类无法验收的话；每一条提案都要能被别人拿去核对。

# 任务

下面是一个**已经有锁定设计系统、但观感与层级仍不满意**的企业级产品前端。请给出一份**界面改进方案**，
目标是：在不破坏既有工程约束的前提下，显著提高（a）页面的层级与焦点、（b）"往里走"那些管理页的设计完成度、
（c）视觉一致性（消除自己跟自己不一致的地方）。

请**先给诊断，再给方案**；方案分三层交付，并明确哪些是"可以直接实施"、哪些是"需要拍板改锁定条款"。

# 产品背景

企业级知识助理平台（RAG 问答 / 知识库 / 应用编排 / 权限管控），用户是政企内部的知识运营、应用配置人员、
管理员与普通提问者。当前处于"重构后、待可用"阶段：接口契约已冻结、页面跑在 mock 上，
主要角色是**干活的人**（长时间在表格、卡片、表单、画布之间切换）。

# 当前界面是什么样（压缩版；如附件 A / 完整文档可用，请以附件为准）

**谱系**：genre = modern-minimal；主题 = "Cobalt" —— 冷调工程白纸 + **发丝线分面** + **一个**电光钴蓝信号色 +
**6px 紧圆角** + 深度靠线不靠影；结构族 = Workbench（应用页）与带框顶栏（外壳）。
生成工具为 Hallmark，已经过两轮改造；系统的自陈判据是：**「克制不带焦点，等于没有设计」**。

**令牌（`tokens.css`，是唯一真源，可迁移）**
- 表面 4 档 + hover：paper `oklch(97.4% .004 252)` / surface `99.4% .002` / surface-2 `99.8% .001` / sunken `95.8% .005` / hover `96.8% .006`。**没有纯白、没有零彩度灰。**
- 线 3 档：rule `90.5% .008 252` / rule-2 `94% .006` / rule-strong `85% .01`。分面全靠 1px 线。
- 文字 4 档：ink `24% .02 258`（标题）/ ink-2 `38% .017`（正文）/ muted `56% .013` / faint `68% .01`。
- **唯一信号色**：accent `oklch(58% .2 256)`、hover `52% .21`、ink `99% .005`、soft `96% .028`、line `88% .055`、focus = accent。**任一视口用量上限 5%**，只许出现在：选中左竖条 / 焦点环 / 链接 hover 下划线 / 一个主按钮 / 状态点。
- 状态：ok `55% .115 158` / warn `62% .13 72` / danger `55% .17 27`，各带一个 `96.5%` 的 soft 底；**只用于标签、圆点、行内文字，不做大面积填充**。
- 深色石墨拍子（`graphite` 22% .016 260 等 7 档）：**一页只许一处**。
- 投影只有两档：`0 1px 2px …/0.05` 与 `0 4px 16px …/0.08`。

**排印**：2+1 三面封顶 —— display `Space Grotesk` / body `Geist` / mono `JetBrains Mono`，汉字回退到本机 CJK 栈（`PingFang SC → HarmonyOS Sans SC → Microsoft YaHei → …`），拉丁面自托管、禁外部 CDN。
字号 8 档：12 / 13 / **14（正文默认）** / 16 / 20 / 24 / 32 / 40，display 段 1.25 比率，**单页最多用 5 档**。
行高两档、不许一刀切：**阅读性文本 ≥1.75**（markdown/消息体/说明段落），**界面 1.6**（表单/表格/密集列表）。
中文四条硬纪律：正文 ≥14px（12px 是下限）· 阅读行高 ≥1.75 · **中文标题字距必须为 0**（负字距只给纯拉丁/数字）· **不用斜体**（强调用字重/信号色/下划线）。
mono 只许占两处：全大写小标签（表头、元信息、状态、kbd）与数字列/ID/版本号/接口路径（必须 `tabular-nums`）。

**间距/圆角/动效**：间距 4pt 九档 `2/4/8/12/16/24/40/64/96`，按角色命名（同级兄弟用 `gap` 不用成串 `margin`）；
圆角 `3/4/6/8/999`（6px 给控件、8px 给卡片、999 只给头像与圆点，仪器面板 10px）；
动效三档 `120/220/420ms` + 三条自定义 bezier，**只动 transform 与 opacity**，禁 bounce/视差/无限循环，焦点环不做过渡，
必须有 `prefers-reduced-motion` 分支。

**外壳**：48px 带框顶栏（全站唯一允许 `backdrop-filter` 的地方），左 = 字标 + 竖发丝线 + **3 组 11 项分组下拉菜单** + 工作台；
右 = 带框的 `⌘K/Ctrl+K` 提示 + **一个**实心钴蓝主按钮 + 用户下拉。`main` 是唯一滚动容器。

**页面族**：
- 应用页（绝大多数）：页头（标题 + 说明行 + 右侧操作区，一律左对齐）→ `.notice` 说明带 → 过滤条 → 卡片网格/表格/主从双栏 → **至多一条**仪器面板。
- 沉浸页（登录 / 公开问答）：允许用掉那**一次**深色石墨拍子 + 一片偏向一侧的有机色场。
- 编排画布（LogicFlow）：**唯一豁免"零装饰"**的区域（节点卡/连线/网格都算功能件），但它是从旧工程移植的，排版节奏与页面族不同源。

**四个签名动作**：① 仪器面板（深色石墨 + mono 标签 + 等宽读数 + 右上角四态胶囊 `OK/RUNNING/WARN/ERROR`，**每视口最多一个**，数据必须真实，**编造指标是最严重违规**）② 深色石墨带（每页至多一条，用途固定为"机器回执/展示时刻"，判据：**去掉它页面会失去一个读数**）③ 命令面板（⌘K，真的能用：跳页 + 动作，按权限过滤）④ 有界 art 层（**限定表面，不放开风格**）：沉浸页色场 / **页头通栏蓝图细网 hatch（0.12）** / 空态 mono 线稿示意图 + 极浅色场 / 石墨带内 hatch（screen 0.6 档）/ 沉浸页颗粒 0.15；素材本地生成、禁外部 URL、**禁暖色**。

**已明确的禁令**（现状守护的，不是你的可选建议）：纯黑/纯白 · 零彩度灰 · 紫→蓝渐变 · 渐变文字 · 毛玻璃（除顶栏）·
彩色左竖条 callout · 投影堆叠 · hero 大标题 · `min-height:100vh` 居中单句 · 三列等宽"图标-标题-两行字"功能格子 ·
卡片套卡片 · 每个区块滚动淡入 · 卡片内边距 = 区块间距 = 页面边距 · 页面直接写 `--el-*` · 内联色值/字族/裸 px ·
`transition: all` · 浏览器默认 `ease` · `:teleported="false"`（会把浮层塞进画布的 foreignObject，用户选不了）·
emoji 塞进 `<img src>` · 可逆动作弹确认框 · 能看见结果的动作弹成功提示 · hover 抬升卡片。

**已知的真实不一致（改进优先处理这些，而不是另起一套）**
1. **页头有两套**：只有工作台用全局 `.page-head` + 24px 标题；其余 12 页用 `PageHeader.vue`，而它写的是裸值 —— `font-size: 17px`（**不在字号阶梯里**）、`gap: 16px`、`margin-bottom: 14px`（不在 4pt 刻度）、`line-height: 1.7`（不走行高令牌）、`margin-top: 5px`。
2. 编排画布自带一套 `--app-*` 别名层与旧类名，**视觉上像另一个产品**；里面还有 `calc(100vh - 56px - … - 40px)` 与 `height: calc(100vh - 560px)` 这类"猜高度"。
3. **art 层与深色带覆盖不均**：`EmptyArt` 只在 2 处、`InstrumentCard` 只在 3 处（工作台/知识库详情/应用概览）。往里走的页面（模型管理/系统管理/基础数据）退化成"一排卡片 + 一片空白"。
4. **层级过平**：只有 5 档可用字号 + 一种强调色，区块标题/卡片标题/正文常只靠 400→500 字重区分，远看是一片均匀的灰。
5. 品牌层是占位（占位字标 + `/favicon.ico` 404）；空态/加载态手段少（默认只有排版 + 发丝线）。
6. 工程闸门有盲区：`字号<12px` 只抓下限（所以 17px 脱阶梯漏过），**裸 px 间距完全不抓**。

# 必须遵守的工程约束（方案落在这些里面）

- **令牌是单行道**：`tokens.css` 定义 → `index.css`（基线/原子类）→ `element-plus.css`（`--el-*` 单向映射）。页面里每个颜色/字体/间距都必须 `var(--token)`；需要新值时必须**先加具名令牌**再引用。
- `frontend/design.md` 是**锁定设计系统**，但它是**可以改的** —— 文档自己写明「系统要长，就改这份文件（加 `## Variants` 或 `## Per-page allowance`），**不要在页面里局部覆盖**」。所以你可以提议**修订 design.md / tokens.css**，但必须显式声明"这条是改锁定条款"，并给出理由与影响面。
- **依赖白名单**（不得新增）：`element-plus` · `@element-plus/icons-vue` · `pinia` · `vue-router` · `axios` · `dayjs` · `lodash-es` · `mitt` · `echarts` · `@logicflow/*` · `@antv/layout`。**不得**引入第二套组件库、商业基座框架模板、`vuex`、`moment`、任何外部 CDN。
- **UI 组件库只有 Element Plus 一套**，`--el-*` 只能由那一个桥接文件映射。
- 权限入口的唯一判据是 `RouteMeta.permission` + 数据范围 `RouteMeta.scopeForms`（经 `canReach()` 统一消费）；**不要给导航项另加权限字段**。
- 所有"状态"都必须真实（不许出现占位数字/假指标）；无数据时显示「—」而不是 0。
- 只能改前端呈现层：**不要**提议改接口契约、mock 结构、后端能力（这些不在本次范围）。

# 交付物（严格按此结构）

## 0. 开工前的问题（可选，最多 5 条）
只问**会改变方案走向**的问题（例如"我必须看到 X 页的截图才能判断"）。若无需提问，写"无需提问"并直接给方案。

## 1. 诊断
按**证据**说话。分三类，每条一句话 + 证据（哪一页 / 哪个组件 / 哪个令牌）：
- A 一致性问题（自己跟自己不一致）
- B 层级与焦点问题（哪里读起来是平的、哪里缺重音）
- C 完成度问题（哪一页/哪一态明显没做完）
**不要**在这里提方案；也不要重复我上面已经列出的 6 条（可以引用编号并补充你没提到的）。

## 2. 方案（三层，逐条编号）
- **层 1 · 系统级**（令牌 / 全局原子类 / Element Plus 桥 / 组件 API / 壳体）：影响面最广、收益最大。
- **层 2 · 页面级**（按页面给）：每个页面说清"改哪一处、为什么、改成什么"。
- **层 3 · 打磨级**（微交互 / 空态 / 加载态 / 错误态 / 文案语气）。

**每一条提案必须给全这 6 项**（缺任一项视为不合格提案）：
| 字段 | 要求 |
|---|---|
| 问题 | 一句可复述的话 |
| 证据 | 页面/组件 + 现有值（尽量具体到令牌名与数值） |
| 改法 | 给出**具体值**：令牌名 + 数值（OKLCH / px / ms）与 CSS 片段；不要形容词 |
| 影响面 | 会波及哪些页面/组件；有没有连带要改的断言或文档 |
| 判据 | 别人怎么核对"改成了"——**最好是可测量的**（例：同屏不再出现两种页面标题字号；某元素相邻像素差 = 0；某页有且只有一个深色重音） |
| 是否改锁定条款 | "否" / "是：需修订 design.md 第 X 节"（是的话附修订后的条文） |

## 3. 两个清单
- **可以直接实施**：不需要我拍板的（按收益/成本排序，标注预估工作量 S/M/L）。
- **需要拍板**：会修改锁定条款或改变产品语气的，附"如果不做会怎样"。

## 4. 自检
逐条回答（是/否 + 一句依据）：
1. 你的方案有没有引入第 8 节禁令里的任何一条？
2. 有没有新增依赖或第二套组件库？
3. 有没有引入阶梯外的字号、刻度外的间距、或非令牌颜色？如果有，是否已显式登记为新令牌？
4. 每个页面是否仍然 ≤5 档字号、accent ≤5%、至多一条深色重音？
5. 中文四条排印纪律是否都还在（≥14px / 阅读行高 ≥1.75 / 标题字距 0 / 无斜体）？
6. 是否有任何"编造数据/占位指标/假状态"？
7. 你提出的每条判据，**能不能被别人独立核对**（而不是"看着更好"）？

# 反面要求（会被直接判为不合格）

- 把"现代感"理解为：毛玻璃、渐变、彩色投影、大圆角胶囊、悬浮卡片、大标题 hero、插画、默认深色模式。
- 提出"加动画让页面活起来"（本项目明确：应用页**零滚动入场**，只做微交互）。
- 用"可以适当…""建议考虑…""更精致一些"这类无法验收的措辞代替具体值。
- 把方案写成组件库替换或整站重做（现状是一套**做得挺扎实**的系统，改进应顺着它长，不是推倒）。
- 提议编造指标、装饰性图表、或"看起来更丰富"的假数据块。
- 只给页面局部 hack 而不指出"这需要新增/修订哪个令牌"（那正是现状第 1 条不一致的成因）。

Markdown。用表格承载逐条提案（列就是上面那 6 项）；CSS 片段用代码块并标明"新增令牌 / 修改令牌 / 页面样式"。
```

## 三、投喂建议（提高产出质量的三件事）

1. **给截图**：① 工作台（最完整的一页）② 一个典型管理页（如模型管理或基础数据）③ 编排画布 ④ 登录页。四张足以让模型判断"层级与焦点到底缺在哪"。
2. **给规模和用途**：说明主要用户在什么屏幕（笔记本 1440×900 为主还是 1920 宽屏）、单次停留时长、是否需要投影演示——这些会直接改变密度与字号取向的策略。
3. **明确"能不能改锁定条款"**：本工程的口径是**可以改**（改 `design.md` 而不是在页面里局部覆盖）。**如果你不这么说，模型会倾向于只给页面级 hack**，那恰好是现状第 1 条不一致的成因。
