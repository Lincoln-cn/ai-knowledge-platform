★ **今晚换来的三条经验（都写进仓库了）**：

1. ★★ **`mvn test` 生命周期自带 `spotless-check`** ⇒ 改一行代码后跑金丝雀，**可能先红在格式闸门**（码名长短变了、换行需求变了）⇒ **必须先 `spotless:apply`**，否则拿到的是"格式红"而不是"断言红"。（今晚 spotless 一共拦下 **4 次**，其中 3 次是我改 javadoc。）
2. ★★ **只要前面的 PR 是 `squash` 合并，就不要再叠层** —— 今晚两次踩到（`#99`/`#100`、`#105`）：`gh pr update-branch` **只把 base 并进 head、不改 base、也不消解分叉**。正解 = **从 `origin/main` 开新分支 + `cherry-pick`**（两次均无冲突）。已写进 `docs/无CI期开发与验证计划.md §七`。
3. ★ **`reset --hard` 会吃掉子代理的未提交改动** —— 今晚因此丢过 9 个文件（靠原执行者的上下文重落回来）。要"干净基线"用 `git switch -c <new> origin/main`。已记 `#49`。
