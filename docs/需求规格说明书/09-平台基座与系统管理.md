# 09 · 平台基座与系统管理

## 一、需求概述

平台建立在**商业级后台基座**之上。基座提供的账号、组织、权限、菜单、租户、日志、任务调度等能力，与 AI 业务无关，但**是业务功能得以运行的前提**：没有账号就没有用户，没有菜单就没有入口，没有租户就没有隔离。

本册的作用是：**明确哪些需求由基座满足，哪些需要按 AI 业务定制**，避免复现时把通用能力当成业务需求重复实现。

> **访问提示**：管理后台**刻意不提供导航入口**，需通过地址栏直连。这是设计意图（见第 1 册 BR-01-03）。

## 二、组织与账号

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-01 | 用户管理 | 部门树 + 用户增删改查；审核（通过/拒绝）；角色配置；密码重置；平台配置；账号解锁 |
| FR-09-02 | 机构管理 | 部门树懒加载增删改查，支持多层级组织 |
| FR-09-03 | 岗位管理 | 岗位增删改查 |
| FR-09-04 | 个人信息 | 查看/修改个人资料与密码 |

> **BR-09-01**：用户管理是**所有业务账号的来源**。业务人员（知识运营、应用配置人员）都必须先在此建号并分配角色，才可能看到工作台对应功能。

## 三、权限体系

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-05 | 角色管理 | 角色增删改查；权限设置（菜单 / 数据 / 接口三个页签） |
| FR-09-06 | 数据权限 | 按菜单配置数据可见范围规则 |
| FR-09-07 | 接口权限 | 按菜单配置接口可达范围规则 |
| FR-09-08 | 菜单管理 | 菜单树维护；区分菜单与按钮；配置路径、图标、排序、缓存、开放状态 |
| FR-09-09 | 顶部菜单 | 横向一级导航的维护与菜单集合配置 |

（权限模型详见第 1 册第三节。）

## 四、多租户 SaaS

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-10 | 租户管理 | 租户增删改查、回收站恢复、授权配置（额度/有效期）、数据源配置、产品包配置 |
| FR-09-11 | 租户产品包 | 将菜单集合定义为产品包并绑定租户 |
| FR-09-12 | 应用（客户端）管理 | 管理平台内的 OAuth2 客户端，决定各端登录使用的身份 |

> **BR-09-02**：**应用（客户端）管理是"两套后台一显一隐"的实现基础**。业务后台与管理后台使用不同的客户端标识，从而得到不同的菜单集合。复现时若客户端配置丢失，会表现为"登录后什么都看不到"。

> **BR-09-03**：平台内置多个客户端标识，分别对应不同前端形态（业务前端、新版管理端、旧版管理端）。**这些密钥在生产环境须加密或走环境变量注入**，不应以明文形式留存。

## 五、配置与字典

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-13 | 系统字典 | 字典主项与子项的维护（如应用分类、模型类型、导入类型、知识领域） |
| FR-09-14 | 业务字典 | 面向业务的分组字典，AI 业务的下拉选项多来自此处 |
| FR-09-15 | 参数管理 | 系统参数（键/值/名称）维护 |

> **BR-09-04**：**业务字典是 AI 业务大量下拉项的来源**。已登记的字典包括：应用分类、应用类型、知识库类型、导入文档类型、知识领域、模型供应商、模型类型、PPT 类型、分段引用设置等。
> **复现时若字典缺失，对应下拉会为空**，导致应用/知识库无法创建。字典数据必须随环境一并准备。

> **BR-09-05**：**参数管理承载若干功能性开关与地址**，例如：新用户初始密码、租户管理员默认密码、爬虫操作手册下载地址、API 文档下载地址。这些参数缺失会导致对应功能不可用。

## 六、资源服务

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-16 | 对象存储 | 配置多个存储服务（当前默认本地对象存储），可分类、启用/停用、调试连通性 |
| FR-09-17 | 短信配置 | 配置短信服务，可分类、启用/停用、调试发送 |
| FR-09-18 | 附件管理 | 上传、下载、删除附件；按业务分类查询 |

> **BR-09-06**：**对象存储是知识库文档、应用图标、PPT 模板、生成产物的统一落地点**。存储服务不可用时表现为"上传失败""图标不显示""生成物下载 404"。这是排查上传类问题的第一现场。

> **BR-09-07**：对象存储支持配置**多个渠道**（本地存储 / 云对象存储 / 云盘），可指定主用渠道。平台默认使用本地对象存储，符合内网部署要求。

## 七、运行与审计

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-19 | 定时任务 | 任务应用与任务配置的增删改查、同步、启停、手动执行 |
| FR-09-20 | 日志管理 | 通用日志、接口日志、错误日志的查询与详情 |
| FR-09-21 | 服务治理 / 监控入口 | 提供若干监控与治理控制台的跳转入口 |
| FR-09-22 | 报表管理 | 报表列表查询、报表设计器、报表预览 |
| FR-09-23 | 授权（License） | 平台授权审核与下载、租户授权管理、授权用户与密钥上传、刷新授权、清理缓存 |

> **BR-09-08**：**日志是排查业务问题的第二现场**（第一现场是运营大屏的异常接口）。接口日志可定位到某个请求的入参与返回，错误日志可定位到堆栈。

> **BR-09-09**：**授权（License）是商业基座的授权机制**。授权到期或未授权会影响平台可用性。复现时须确认授权状态，否则可能出现"功能突然不可用"的误判。

## 八、开发与运维工具

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-24 | 代码生成 | 按数据表生成后端与前端 CRUD 代码 |
| FR-09-25 | 数据源管理 | 维护多个数据源连接 |
| FR-09-26 | 数据模型设计 | 配置表结构与模型信息 |
| FR-09-27 | 行政区划 | 区划树维护、下级新增、导入/导出、调试 |

> **BR-09-10**：开发工具类模块**对业务人员无用**，复现时可选择性交付。但**数据源管理**与**数据模型设计**是二次开发的基础设施，不建议裁剪。

## 九、工作流引擎（与 AI 编排不同）

> **重要区分**：平台内存在**两套"工作流"**，用途完全不同，切勿混淆。

| 维度 | 平台工作流引擎 | AI 应用编排（第 4 册） |
|---|---|---|
| 用途 | 通用审批流（请假、报销等） | AI 问答流程编排 |
| 使用者 | 全体员工的审批事务 | 应用配置人员 |
| 页面 | 流程模型/部署/管理/跟踪 + 我的事务 | 应用编排画布 |
| 业务相关性 | **与 AI 业务无关**（基座自带） | AI 业务核心 |

平台工作流引擎提供的能力：

| 编号 | 模块 | 能做什么 |
|---|---|---|
| FR-09-28 | 流程模型 | 模型创建、编辑、部署、下载、删除 |
| FR-09-29 | 流程部署 | 部署流程定义 |
| FR-09-30 | 流程管理 | 变更状态、查看流程图、删除 |
| FR-09-31 | 流程跟踪 | 查看流程实例执行轨迹 |
| FR-09-32 | 我的事务 | 发起、待签、待办、已发、办结 五类事务；签收、办理、详情、跟踪 |

> **BR-09-11**：**平台工作流与 AI 业务无耦合，属于基座附带能力。** 若客户不需要审批流，这部分可以整体裁剪，不影响 AI 问答链路。需在需求评审时明确是否保留。

## 十、业务规则汇总

| 编号 | 规则 |
|---|---|
| BR-09-12 | 管理后台无导航入口属设计意图，需保留 |
| BR-09-13 | 两套后台靠客户端标识区分菜单，客户端配置丢失会导致登录后无菜单 |
| BR-09-14 | 业务字典缺失会导致业务下拉为空、无法建库建应用，必须随环境准备 |
| BR-09-15 | 系统参数承载功能开关与外部地址，缺失会导致对应功能不可用 |
| BR-09-16 | 对象存储是全部上传与产物下载的依赖，故障表现为上传失败/下载 404 |
| BR-09-17 | 平台工作流引擎与 AI 编排是两套独立能力，不可混淆 |
| BR-09-18 | 授权（License）到期会影响平台可用性，复现前须确认状态 |

## 十一、验收标准

| 编号 | 验收项 |
|---|---|
| AC-09-01 | 新建一个用户并分配角色，该用户登录后能看到对应菜单 |
| AC-09-02 | 通过菜单管理新增一个业务菜单（指向已存在的页面），用户刷新后可见 |
| AC-09-03 | 新建租户并绑定产品包，该租户只能看到产品包内的菜单 |
| AC-09-04 | 在业务字典中新增一个分类选项，业务页面对应下拉中出现该项 |
| AC-09-05 | 对象存储配置正确时，知识库文档上传成功；停用后上传失败（验证依赖关系） |
| AC-09-06 | 日志管理中能按时间查到刚才的一次接口调用记录 |
| AC-09-07 | 定时任务可手动执行一次并看到执行结果 |
| AC-09-08 | 授权页面可查看当前授权状态 |

## 十二、复现时的最小交付建议

若目标只是"让 AI 问答跑起来"，以下基座模块为**必需**：

| 必需 | 说明 |
|---|---|
| 用户、角色、菜单、客户端 | 否则无法登录与看到功能 |
| 租户（单个默认租户即可） | 数据模型依赖租户标识 |
| 系统字典、业务字典、参数 | 否则下拉为空、功能开关缺失 |
| 对象存储（附件管理） | 否则无法上传文档 |
| 日志 | 排障必需 |

**可选（按客户需求裁剪）**：平台工作流引擎、报表、短信、代码生成、数据源管理、行政区划、授权审核、服务治理入口。
