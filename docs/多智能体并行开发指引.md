# 多智能体并行开发指引

> 适用：把一个批次拆给多个智能体同时推进。
> 判据来源：本项目 2026-10 至 11 月发版过程中**实际踩过的冲突**，不是通用方法论。
> 与 `docs/ROADMAP.md §11.8`（前后端三格配对）、`§11.7`（留缝 vs 只记账）配套使用。

---

## 〇 一句话

**能不能并行，不看"任务觉得独立"，看三件事：写面不重叠、共享单值不争抢、验面不抢资源。**

三条缺一，就不是并行而是"两个人抢同一支笔"。

---

## 一 三条判据

### 判据 1：写面不重叠（文件集合交集为空）

不只看 `src/main`，要**把这三样一起算进去**：

| 也算写面 | 为什么 |
|---|---|
| `backend/src/test/**` | 改一个构造器，7 个测试文件全要跟着改（`ChatService` 加 `MultiHopService` 时就是如此） |
| `docs/ROADMAP.md` 的同一节 | 两个人同时往 `§11.10` 末尾追加，**编号必撞** |
| `frontend/src/api/*.ts` 的类型 | 它是**多条页面共享**的契约层，改一处影响多页 |

★ **反例（真实发生）**：`#283` 改 `ChatService` 构造器 + `#293` 改融合排序，两条都想动 `ChatService.java` ⇒ 必须串行，尽管 `#293` 的核心逻辑在 `Rrf.java`。

### 判据 2：共享单值不争抢

本项目的"全局唯一值"清单见 §二。**这些值必须在派发前一次性分配完**，否则两路各自取"下一个可用值"就必然撞。

### 判据 3：验面不抢资源（端口 / 数据库 / `target/`）

| 资源 | 抢了会怎样 |
|---|---|
| `target/` | 并发 `mvn` 互踩，报 `NoClassDefFoundError`、**红绿都不可信** |
| 端口 18088 / 5281 / 11999 | 新旧实例抢端口，新实例 `exit 1`，你以为起的是新代码 |
| Postgres 库 | 测试用 Testcontainers 各自独立；**手工验证共用一个库时，一个人改的数据是另一个人的读数** |
| ollama 11434 | 两槽位（`qwen2.5:1.5b` + `bge-m3`），第三个模型进来就互相卸载 ⇒ B4 读数变成 25 秒 |

## 二 共享单值清单（派发前必须分配）

| 单值 | 位置 | 分配方式 |
|---|---|---|
| **迁移版本号** | `backend/src/main/resources/db/migration/{模块}/V<N>__*.sql` | ★ **全局唯一**（`locations: classpath:db/migration` 是同一棵树）⇒ 派发前按 `V67`、`V68`…**逐个点名**，不许"自己挑一个空的" |
| **`ROADMAP §11.10.N` 编号** | `docs/ROADMAP.md` | 同批派发时**预分配号段**（如 A 用 95–97、B 用 98–100） |
| **`CaliberShape.MIGRATION_FILES`** | `backend/src/test/java/cn/lincoln/aiplatform/caliber/CaliberShape.java:61` | 每个加迁移的批次**各自加一行**，谁最后合并谁负责对齐顺序 |
| **`ContractDriftTest` 的 missing 清单** | `backend/src/test/java/.../ContractDriftTest.java` | 只在"契约已登记但实现未落"时加 |
| **`verify_permissions.py` 期望矩阵** | `frontend/verify_permissions.py` | 加菜单/加权限点时同步 |
| **`Permissions.ALL` + `PermissionCatalog.ITEMS`** | 两个文件，**必须同改** | 见 §八 坑 3 |
| **CI 的 `gates=(...)` 数组** | `.github/workflows/ci.yml` | 新闸门脚本要注册；**同一行数组，两路同时加必冲突** |
| **`tools/consumer-baseline.txt`** | 零消费端点基线 | 同上 |

## 三 可以并行的域（按写面切，已验证）

并行度**最高 3 路**（再多，`target/` 与验证环境就压不住）。

| 域 | 写面 | 与谁天然不冲突 | 备注 |
|---|---|---|---|
| **后端 · 知识库链路** | `knowledge/`（90 文件）+ `ingestion/` + `vectorindex/` | 与 `identity/`、`modelcatalog/`、前端任意页 | 解析/分段/向量化/入库 |
| **后端 · 会话与检索** | `conversation/`（74）+ `retrieval/`（15）+ `feedback/` | 与 `knowledge/` **有交叉**：都碰 `platform/retrieval/*` 端口 | ★ 若要动 `RetrievalParams` 这类值对象，**先串行改完再分** |
| **后端 · 身份与权限** | `identity/`（55）+ `platform/access/` | 与上面两路基本不冲突 | 但 `platform/access/` 是全平台被引用的端口，**改它的形状要单独立项** |
| **后端 · 模型与服务商** | `modelcatalog/`（50）+ `platform/domain/CryptoPort` | 独立 | |
| **前端 · 单页面** | `frontend/src/pages/<一个目录>/` | 页面之间零交集 | ★ 但共用的 `components/`、`lib/`、`api/` **不算** |
| **前端 · 闸门脚本** | `frontend/check_*.py` 各一个文件 | 独立 | 注册位在 `ci.yml` 的 `gates` 数组（§二） |
| **文档 · 设计册不同册** | `docs/系统设计方案/0X-*.md` 各一册 | 独立 | ★ `06` 与 `ROADMAP` 都写"§11.x"但**是两套编号**，别串 |

### 天然的"三层"切法（推荐）

```
第 1 层（互不冲突）：后端 A 模块  |  前端 B 页面  |  文档/闸门 C
第 2 层（合并后）：  联调与真栈读数（必须串行，抢服务）
第 3 层（合并后）：  发版（版本号三处 + tag + Release，必须串行）
```

## 四 不可并行（必须串行）

| 类型 | 为什么 | 例子 |
|---|---|---|
| **同一文件链式改动** | 一改构造器签名，所有调用点全要改 | `ChatService` 加 `MultiHopService` ⇒ 7 个测试文件 + 1 个内部类 |
| **迁移号** | 全局唯一 | `V54` 撞车（`knowledge` 的与 `platform` 的）⇒ Flyway `Found more than one migration with version 54` |
| **`ROADMAP` 同一节追加** | 编号必撞 | 两边都从 `§11.10.36` 起编号 ⇒ 一方整体 +N 平移 |
| **发版动作** | 版本号三处 + CHANGELOG + tag + Release | 分散做会出现"tag 打在错的提交上" |
| **架构闸门相关改动** | 位置合法 ≠ 类型被暴露 | 见 §八 坑 1 |
| **任何"改全局配置"** | `application.yml` 被所有模块读 | 加 `app.*` 键要同步 `deploy/README.md`（有闸门查这个） |

## 五 环境隔离（并行时按这个分）

| 路 | 后端端口 | 前端端口 | 数据库 | 服务 |
|---|---|---|---|---|
| A | **18088** | **5281** | 共用 `aip-postgres`（读为主） | 需 ollama |
| B | **18089** | **5282** | 同上 | 需 ollama |
| C | 只跑单测（Testcontainers 自带） | — | 独立容器 | 不需要 |

★ **`target/` 是共享的**：并行跑 `mvn` 必互踩 ⇒ 规则是**同一时刻只有一路在跑 `mvn`**，其余用 `git worktree` 各占一份：

```bash
git worktree add ../aip-wtA -b feat/batch-a
git worktree add ../aip-wtB -b feat/batch-b
```
★ 但 worktree 有代价：`#49` 就是 worktree 切出来后**再没跟过 main**，最后比 main 少一千多行。⇒ **worktree 只用于"当天就要合"的短批次**，长期分支不要 worktree。

### 启动命令（照抄，别自创）

```bash
# 后端
export JAVA_HOME="D:/Java/jdk-25"
AI_BASE_URL="http://127.0.0.1:11434/v1" mvn -o spring-boot:run \
  -Dspring-boot.run.arguments="--server.port=18088 --app.security.captcha.enabled=false"
# 必须 run_in_background；重启前先 netstat -ano | grep ":18088" | grep LISTENING
# 取 PID 再 taskkill //PID <pid> //F，否则新实例抢不到端口 exit 1 而你以为起的是新代码

# 前端真栈
cd frontend && VITE_USE_MOCK=false npm run dev -- --port 5281
# .env.development 默认 VITE_USE_MOCK=true，不改就是 mock

# 容器
docker start aip-postgres aip-ollama
```

## 六 派发模板（委托书必须写这六项）

一个子智能体**看不到**主会话的历史，所以委托书要自洽：

```
1. 目标与判据      —— 做什么、怎么算做完（判据要可核对，最好附命令）
2. 写面清单        —— 允许改哪些文件/目录；明确"不许改"的（如 ROADMAP 某节）
3. 预分配的共享值  —— 迁移号 V67、ROADMAP §11.10.95、CI gates 第 N 位
4. 环境            —— 端口、是否用 worktree、JAVA_HOME、服务是否已在跑
5. 已知的坑        —— 从 §八 里挑与本批相关的，直接抄给它
6. 交付形状        —— 提交信息要写什么、要不要开 PR、报告里必须含哪些读数
```

★ **第 3 项最容易被漏**，而它正是撞车的唯一来源。
★ **第 5 项的价值**：坑是"读起来像小事、代价是一小时"的东西，写在委托书里比事后重跑便宜。

## 七 验收与合并

### 每路自己的绿（不许互相继承）

| 改动类型 | 必跑 |
|---|---|
| 后端任何代码 | `mvn -o -q spotless:apply` → 改的**单个**测试类 → 架构闸门两条通配符 |
| 后端改值对象/构造器 | 上面 + **全量**（`-Dtest=cn.lincoln.aiplatform.*Test` 与 `caliber.*Test` 两条各跑一次） |
| 前端 | `npm run typecheck` + 单测 + 改动的那个闸门脚本（含 `--self-check`） |
| 文档/闸门 | 对应 `check_*.py` + `--self-check` |

★ **架构闸门两条通配符缺一不可**：`*` 不跨包，`cn.lincoln.aiplatform.*Test` 只匹配顶层包那 8 个类，`caliber` 一族全在 `cn.lincoln.aiplatform.caliber` ⇒ 只跑一条会漏真实红。

### 合并顺序（固定）

```
① 先合"改共享单值"的那一路（迁移号、Permissions、CI gates）
② 再合"只读共享单值"的那一路
③ 最后合文档/台账（避免编号再撞一次）
④ 全部合完，跑一次全量，再发版
```

### 合并冲突预案

- **迁移号撞了** ⇒ 后来者改号（改大），同步 `CaliberShape.MIGRATION_FILES`；★ 改号后必须 `mvn clean`，否则 `target/classes` 残留旧文件名会继续报撞车
- **ROADMAP 编号撞了** ⇒ 后合并的一方**整体平移**，并在提交信息里写清平移区间
- **API 契约撞了** ⇒ 以 `src/api/**` 为准改实现，**不许让页面直接引 `@/lib/http`**

## 八 已知的坑（挑与本批相关的抄进委托书）

1. **"方向合法"≠"类型被暴露"** —— `ModuleBoundaryTest` 允许 `conversation → retrieval` 方向，但 import 具体实现类会被"non-exposed type"拦。跨层要**加端口（`platform/`）+ 适配器**，不是把实现类开成 `@NamedInterface`。
2. **给会被外部 JSON 反序列化的 record 加字段，必须用包装类型** —— 基本类型遇字段缺席 = null ⇒ 杰克逊 3 报 `Cannot map 'null' into type 'boolean'`，而对外文案只是"请求体不是合法 JSON"，**会把你引向错误的层**。
3. **加权限点要改两处，且不需要迁移** —— `Permissions.ALL` + `PermissionCatalog.ITEMS`；只改前者 ⇒ **ADMIN 也 403**（`syncRolePermissions` 按 `items` 过滤 ADMIN 期望集）。ADMIN 授权是启动时差分计算的，写迁移是多此一举。
4. **`mvn -o -q compile` 会假绿** —— 增量编译可能跳过；`javap -p` 只列成员、证明不了调用点（要用 `javap -c -p | grep "Method xxx"`）；必要时 `rm target/classes/.../Xxx.class` 再编。
5. **spotless 先于编译** —— 格式不合直接 BUILD FAILURE；`for (Segment segment : affected) {}` 这种空块会被拦，而 `exit=1` 不等于"断言红"。
6. **闸门要能红，且要能证真** —— 修完要跑 `--self-check`；正证绿 + 反证红才算一条闸门。★ 还要防**空真**（0 节点时"没有坏节点"平凡成立）。
7. **CI 的"三方地址"** —— 起服务的端口、探活的端口、被测代码连接的端口**三处必须一致**。`#291` 修的是这条，`86a4d92` 又发现第四处（`AI_BASE_URL`）。
8. **`gh issue comment --body` 传长文会报 `accepts 1 arg(s), received N`** ⇒ 写 `.build/xxx.md` 用 `--body-file`。
9. **长跑命令用 `run_in_background`** —— `nohup ... &` 在工具里会被回收。
10. **读数前先排除"服务未就绪"** —— 后端刚启动时 `/retrieval/test` 会返回 0 命中，等 100 秒再测就正常；**"0 命中"不等于"检索坏了"**。

## 九 一个批次的标准形状（照抄）

```
00 前置（串行，主会话做）
   - 分配共享单值（迁移号 / ROADMAP 号段 / CI 位置）
   - 确认 main 基线、干净工作区
   - 决定并行度（≤3）

01 并行（各路独立 worktree 或 独立目录）
   - A: 后端模块 X（含自己的测试）
   - B: 前端页面 Y（含自己的闸门脚本）
   - C: 文档/闸门（不与 A/B 同文件）

02 收口（串行，主会话做）
   - 逐路跑绿（不继承旧的绿）
   - 按 §七 顺序合并
   - 全量回归一次
   - 台账/ROADMAP 记读数
   - 发版
```

## 十 不该并行的四种"看起来能并行"

| 表面上 | 实际 |
|---|---|
| "两路都在改检索" | 都碰 `platform/retrieval/RetrievalParams` ⇒ 串行 |
| "A 改后端、B 改前端，当然能并行" | 若 A 改的是**契约**（`api/*.ts` 的类型），B 立刻编译不过 |
| "B 只改文档，不影响编译" | `deploy/README.md` 有闸门在查（`check_config_docs.py`），改错就红 |
| "两路各自跑测试，互不影响" | 共用 `target/`，并发 `mvn` 的红绿都不可信 |

## 附：本指引自身的判据

一份并行指引若只写"要注意冲突"，等于没写。本文的可核对性在于：

- §二 的每一项都能 `grep` 到具体文件与行号；
- §八 的十条都对应一次真实的红或一次返工；
- §九 的形状可以直接当派发模板用；
- 若哪天某条被判据推翻（例如迁移号不再是全局唯一），**这一节要跟着改**，不能只改代码。
