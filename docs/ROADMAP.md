[`系统设计方案/04-MVP最小验证系统设计.md`](系统设计方案/04-MVP最小验证系统设计.md)，

## 二、「可用阶段」的定义

**这是转公开（private → public）的门槛。** 三张清单全绿才算到。

### 2.1 功能清单（端到端场景全部走通）

`04` §三 定义的三个场景，在 `VITE_USE_MOCK=false` 下无阻塞完成：

| 场景 | 内容 | 验证的假设 |
|---|---|---|
| **S1** | 知识运营：建库 → 上传真实文档 → 切分 + 调参 → 向量化（真实进度）→ 命中测试 → 停用分段后不再命中 | H1、H3 |
| **S2** | 应用配置：建应用 → 选模型 → 写提示词 → 绑知识库 → 发布 → 生成公开链接 → 外部访客未登录提问得带引用答案 → 撤销后 1 分钟内失效 | H3、免登录安全 |
| **S3** | 终端用户：流式作答 → 引用可展开溯源 → 连续追问 5 轮 → 生成中停止保留已生成内容 → 重新生成 → 赞/取消赞刷新后仍在 → 会话评分 | 交互完整性 |

### 2.2 数据真实性清单（`04` §6.2 的 A1–A9）

**A2 是最容易被绕过、也最能说明问题的一条**：任意时刻的进度与状态必须与数据库实际状态一致，
**刷新页面不重置**。前端现在的进度是 mock 推进的 —— 这一条通过，就等于"后端真的接管了状态"。

A1 全链路 · A2 状态真实性 · A3 失败可见（人为构造失败，界面给出可读原因与重试）·
A4 引用可溯源 · A5 停止与重生成 · A6 多轮上下文（10 轮仍能指代第 1 轮实体）·
A7 权限生效（前端看不到按钮 **且** 直接调接口被拒）· A8 免登录安全 · A9 模块边界校验通过。

### 2.3 质量与工程清单

| 项 | 门槛 |
|---|---|
| 量化指标（`04` §6.3） | **B1 命中率 ≥70%** · **B2 答案可用率 ≥75%** · B3 引用准确率 ≥80% · **B4 首字延迟 ≤10s**（CPU/4B）· B5 完整回答 ≤60s · B6 入库 ≥3 段/秒 · B7 连续 200 次问答无未处理异常 |
| 前端闸门 | `vue-tsc` 0 · 模板配平 · 设计系统维度全 0 · `build:mock` ✓ · 11 个脚本 exit 0 · console 0 |
| 后端闸门 | 架构校验测试通过 · 关键链路集成测试通过 · **契约漂移检测**通过（见 §七） |
| 工程 | **CI（GitHub Actions）跑通**：前端 11 个脚本 + `vue-tsc`/`build` + 后端四类闸门 · `docker-compose.yml` 一条命令起（应用 + PG/pgvector + 模型网关）· 示例数据种子 |
| 文档 | 面向贡献者的「如何加一个模块」· CHANGELOG 起点 |

> **B1/B2 不达标不是"功能没做完"，而是假设 H1 不成立** —— 此时正确的动作是回机制二（检索策略）
> 与问答对（P2 升 P0）做优化，**不是继续加功能**。这条判断规则写在计划里，是为了在指标不达标时
> 有据可依地不乱改方向。

### 3.5 ★ 权限模型缺了一层：只有「操作」，没有「范围」

**这是本轮发现的、影响面最大的一处设计缺口。** 详细设计见
[`系统设计方案/07-角色与数据权限模型.md`](系统设计方案/07-角色与数据权限模型.md)，此处只记差距。

| # | 事实 | 读数 |
|---|---|---|
| 1 | 权限点 **13 个，全是"操作"** | `knowledge:view` 是**无参数**的 —— 能回答「能不能看知识库」，**回答不了「能看哪些」** |
| 2 | 契约里**归属/可见性字段 0 个** | `owner` / `visibility` / `sharedWith` / `orgId` 全无 |
| 3 | `Role` 类型**没有数据范围的表达位** | 只有 `permissions: string[]` |
| 4 | **旧系统是三层权限**（菜单 + **数据** + 接口，`FR-01-05`） | 新系统只有菜单（路由 meta）+ 接口（权限点）⇒ **数据层丢了** |
| 5 | ⇒ **普通用户看到的是「整个工地，只是按钮少几个」** | `USER` 只有 **2 个权限点**，却看到 **4 个模块**，其中 `知识库` 与 `应用管理` 是**全平台建设面** |

**为什么不能靠加权限点解决**：那是**集合关系**（自己的／被共享的／全平台的），
不是**动作** —— `knowledge:view` 加多少前缀都表达不了。

**处置（已写进 07）**：引入 `ownerId` + `visibility` + `sharedWith`（资源侧）与
`dataScope: own | shared | all`（角色侧），可见性判定**只在后端一处实现**；
并把「普通用户」拆成 **使用者**（纯消费）与 **个人建设者**（能建自己的）两个角色。
`04` 里「MVP 采用全员可见」那条口径**已作废**。

**四件待拍板**（07 §七）：管理员能否看别人的会话 · `CREATOR` 能否建编排应用 ·
`public` 可见性是否进 MVP · 新建资源的默认可见性。**建议四条全选"默认收窄"** ——
数据权限放开容易、收回难。

## 四、里程碑总表
**规模**：后端 2 人 + 前端 1 人 +（兼）测试 1 人（`04:302`）。人力不同按比例缩放。

**覆盖度对账**：前端契约共 **98 个端点**（12 个域 + `POST /auth/refresh`），下表把它们**全部**落到里程碑上。

| 里程碑 | 模块（端点数） | 交付物 | 预计 |
|---|---|---|---|
| **M0 · 骨架** | `platform` 共享内核 + 11 模块骨架（0） | 可启动的空系统 + **架构边界校验测试通过** + Flyway 迁移框架 + 鉴权框架 + CI + **Spring AI 接入验证 + 模型能力探测 + 参数下发核实** | 1 周 |
| **M1 · 身份与模型** | `identity`(11) + `modelcatalog`(8) + `POST /auth/refresh`(1) = **20** | 能登录、能注册并加载一个模型 | 1.5 周 |
| **M2 · 知识库与入库** | `knowledge`(7) + `ingestion`(14) = **21** | **能上传文档并变成可检索的分段** | 3 周 ★关键 |
| **M3 · 检索与命中测试** | `retrieval`(3) + `vectorindex`（基础设施，无对外端点）= **3** | 能看到命中结果并调参 | 1.5 周 ★关键 · ⚠️ **只含"基础检索"**；策略层（改写/扩展/分解/多跳）见 `10 §10.2`，**建议拆 M3a/M3b**（待拍板） |
| **M4a · 应用配置与发布** | `assistant`(17) + `prompts`(8) = **25** | 能配置、发布应用并生成公开凭证 | 1.5 周 |
| **M4b · 问答链路** | `conversation`(9) + `stream`(1) = **10** | **能问答并看到引用** | 1.5 周 ★关键 |
| **M5 · 反馈与看板** | `feedback`(5) + `analytics`(4) = **9** | 能收集反馈并看到用量 | 1 周 |
| **M5.5 · 编排配置面**（本计划补位） | `workflow`(10) = **10** | 能画流程、存草稿、校验、发布版本、回滚、看流程记录 | 1.5 周 |
| **M6 · 端到端验证与调优** | — (0) | **验收报告（B1–B7 实测值）** | 2.5 周 |

**合计 15 周。** 比 `04` 的 13.5 周多 1.5 周，增量全部来自 **M5.5** —— `04:67` 明说编排配置界面进 MVP，
但它的 §七 里程碑表没有给这一块落位。这是一处真实的范围漏算，不是估算变松。

**关键路径：M2 → M3 → M4b。** 这三段占总量约 60%，且 M2 的分段质量直接决定 M4b 的问答质量。

### 4.1 每个里程碑的验收怎么量

| 里程碑 | 验收口径（可复核） |
|---|---|
| **M0** | ① `ApplicationModules.verify()` 通过；故意加一处越界依赖 ⇒ **构建失败**（金丝雀）② `docker-compose up` 能起空系统 ③ **交付两份结论**：各模型的思考三态取值、Spring AI 能否下发思考开关参数。**这两份结论是 M2 的入口条件**，不是文档 |
| **M1** | 登录成功 + 令牌刷新（401 静默重试一次）+ 权限点下发；注册并加载一个模型 ⇒ 状态从「加载中」变「已加载」（**加载态存服务端**，刷新页面仍在） |
| **M2** | 上传真实文档 ⇒ 状态机走完七态；**A2**：任意时刻进度与数据库一致、刷新不重置；**A3**：人为构造解析/向量化失败 ⇒ 界面给出可读原因与重试 |
| **M3** | 三种检索模式都能出结果；混合模式走 RRF；阈值先于 TopN；命中测试页可调参并看到相似度与来源 |
| **M4a** | 发布校验**两档分化**：简单应用查提示词/检索项，编排应用查「流程已配置」并逐节点校验模型已加载；`published=true` 会重跑校验并拒绝不合格；凭证撤销是终态（不可重新启用） |
| **M4b** | **A4** 引用可展开溯源 · **A5** 停止保留已生成内容、重生成用同一问题 · **A6** 连续 10 轮仍能指代第 1 轮实体 · **A8** 撤销凭证后原链接 1 分钟内失效。SSE 事件顺序固定 `meta → refs → delta* → artifact → done`（`error` 后仍走 `done`） |
| **M5** | 赞/取消赞互斥可撤销且**刷新后仍在**；「已处理」必须填处理说明；满意度无数据时为 `null` 而非 `0` |
| **M5.5** | 能画出流程并存草稿（草稿允许不合规）；发布要求零错误 + 备注；版本列表、回滚（只生成新草稿）、流程记录。**校验规则必须逐条复刻前端 `pages/workflow/lib/validate.ts:226-385`**（唯一 start / 禁环 / 孤立断链 / 分支出边+兜底 / 空表达式 / 数值条件完整 / 模型库引用存在 / 无回复告警） |
| **M6** | 三场景无阻塞 + A1–A9 全过 + B1–B7 实测值写进验收报告 |

### 4.2 M4 是全表最拥挤的一段，先拆

`04` 把「应用配置 + 发布 + 公开凭证 + 流式问答 + 引用 + 多轮 + 停止/重生成」压在 3 周里，
共 **35 个端点**，且包含全项目最难的单点（SSE 流式契约）。

**拆成 M4a / M4b**，理由是这两半的**耦合面很窄**：M4a 是「写配置」，M4b 是「跑问答」，
两者之间只有"发布后的应用可被问答"这一条连接（通过 `assistantId` + 公开凭证）。

拆开的好处是**关键路径更短**：M4a 可以与 M3 并行（它只依赖模型与知识库存在，不依赖检索质量），
只有 M4b 必须排在 M3 之后。

## 五、前端并行轨

前端在 MVP 范围内还差四件事（§3.3 的缺口），它们**不阻塞后端**，但阻塞「可用阶段」。

| # | 事项 | 为什么它是门槛 |
|---|---|---|
| F1 | **编排画布接契约** | 10 个 `workflow` 端点目前**零调用**。接上之后 M5.5 才算有前端；同时把 `workflow`/`prompts` 补进 `api/index.ts` 并改掉 `prompts/Index.vue:57` 的绕过引用 |
| F2 | **首次引导** | 「建知识库 → 传文档 → 建应用 → 试问答」的最短路径 + 进度。现在全库没有引导，外部用户进来没有起点 |
| F3 | **公开分享链路补完** | 生成分享链接的入口 + 凭证失效/撤销后的提示。S2 的最后一环 |
| F4 | **空态与错误态盘点** | 现在是"能用"级；外部用户对空态/失败态的容忍度低得多 |

**排序**：F1 跟着 M5.5 走；**F2 应最早启动**（它不依赖任何后端能力，且直接决定开源第一印象）；
F3 跟着 M4a/M4b；F4 在 M6 前收口。

**一条纪律**：前端改动**照旧要过 11 个脚本 + 自己读图**。上一轮刚证明过——11 个脚本全绿时，
图上仍能一眼看到问题（指标条 800px 空白），而 `shot_sweep` 那次"12 张截图里 2 张拍的是别的页"
是靠**哈希去重**才发现的，闸门当时全绿。

| P1 | **测试语料 ≥50 份真实业务文档**（≥200 万字，覆盖 PDF/Word/Markdown）+ **问题集 ≥50 个真实问题**（每个标注期望命中的文档与段落）+ ≥2 名业务评审人 | 用演示数据验证出来的 RAG 结论没有意义（**效果强依赖语料特性**）。且业务人员整理需要两三周 | **M2 期间就要启动**，M6 用 |

### 6.2 已被架构决策消解的项（不必再准备）

`需求规格说明书/10` 列了 4 个"复现旧系统"的阻断项。**这套后端是自建、schema 与权限点都由代码定义**，
所以其中 3 项对本计划**不构成阻断**：

| `10` 的阻断项 | 为什么不再阻断 |
|---|---|
| 15 张业务表缺 `CREATE TABLE` | 新后端**自建 schema**：表命名 `<模块前缀>_<实体>`、UUID 主键、Flyway 每模块一个迁移目录、向量表 `vec_embedding` 用 `vector(768)` + HNSW cosine（`02:500-524`、`02:593-603`）。**旧表结构只在做数据迁移时才需要** |
| 业务菜单树未交付（169 条全是基座菜单） | 新前端的导航来自路由 + `meta.permission`，**权限点是代码常量**并在后端启动时同步（`frontend/src/constants/permissions.ts`、`03:568`）。不需要"从库里配一条" |
| 业务字典 / 系统参数缺失 | 新系统里知识库分类是**用户自建 CRUD**（`knowledge/listKnowledgeCategories`），不是预置字典 |

**唯一仍需业务输入的是"业务定义"本身**（比如分类怎么划、初始密码策略），那是需求确认，不是数据导出。
`10:300` 那句 *"代码是可复现的，数据不是"* 针对的是**复现旧系统**；本项目的路径是重建，所以不适用。

### 7.1 前端（现成，直接进 CI）

### 7.2 后端（新增四类）

| 类型 | 内容 | 为什么 |
|---|---|---|
| **架构测试** | `ApplicationModules.verify()` + 依赖矩阵 | 把"模块边界"从约定变成**构建期失败**。配金丝雀：故意加越界依赖必须让构建红 |

| **关键链路集成测试** | **Testcontainers 2.x**（`pgvector/pgvector:pg16`）+ `@ServiceConnection` 跑：入库七态状态机 · 检索三模式含 RRF · SSE 事件顺序 · 权限拒绝（**不用 H2 / 不 mock 数据库** —— 我们的复杂度几乎全在数据库上） | A2/A3/A4/A7/A9 的实现手段 |
| **冒烟** | 对着真后端跑一遍前端的三场景 | S1/S2/S3 的自动化形态 |

### 7.3 完成定义（DoD，`04:288-296`）

一个功能算"完成"需要满足：① 领域不变量在**应用层与数据库层都有兜底** ② 有自动化测试（领域单测 + 关键链路集成）
③ 失败路径有可读提示、**不存在静默失效** ④ 关键操作有日志与指标埋点 ⑤ 前端按钮已接权限点
⑥ 模块边界校验通过 ⑦ **已在真实语料上手工验证过**。

> 第 ⑦ 条是最容易被跳过的一条。第 ③ 条是本项目**这个会话里已经栽过五次**的那一类 ——
> 「报红会有人修，'少了一条'没人会注意到」。

## 八、风险与决策点

### 8.1 风险（`04:342-356`，按需关注四条）

| # | 风险 | 应对 |
|---|---|---|
| **R9** | 模型思考能力探测不准 / Spring AI 无法下发思考开关 | **M0 就把两件事做完**；端口已隔离，绕过后走原生适配器 |
| **R3** | **解析质量差（PDF 表格、扫描件）** —— 概率被明确低估 | **M0 就拿 10 份真实文档做解析测试**，不要等到 M2。MVP 明确不支持扫描件 |
| **R1** | 本地模型质量不足（H2） | **M1 结束立即做小规模问答试跑**，不要等 M6 |
| **R7** | 范围蔓延 | §3.1 那三处"前端跑在前面"的项**要明确记账**（相当于 V0.2 提前做），但不能因此把 V0.2 整体前移 |

### 8.2 决策点（`04:377-397`）

M6 结束时基于 B1–B7 实测值做一次正式复盘：**H1 不成立**（命中率 <70% 或可用率 <75%）
⇒ 进入优化循环（调分段 → 换向量模型 → 启用问答对 P2 升 P0），**而不是继续加功能**；
**H2 不成立**（首字延迟 >10s）⇒ 评估 GPU / 换小模型 / 接在线模型；**H3 不成立**
⇒ 重新评估产品定位（大幅简化流程，或明确"实施服务"是交付的一部分）。

**这个决策点的存在本身就是计划的价值** —— 它把"要不要继续投入"变成有数据支撑的判断。
