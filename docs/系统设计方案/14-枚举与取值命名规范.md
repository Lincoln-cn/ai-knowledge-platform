# 14 · 枚举与取值命名规范

> 本文是**可执行的规格**，不是倡议。它回答一件事：
> **一个枚举的标识符、线上值、库存值、展示文案，各自写成什么样子、放在哪。**

---

## 一、规则（三条，别再分叉）

| # | 规则 | 说明 |
|---|---|---|
| 1 | **标识符 = 线上值 = 库存值**，三者同名，一律 **`SCREAMING_SNAKE_CASE`** | 全大写；**多词用下划线**分隔（`EXTERNAL_API`、`LOAD_FAILED`、`PENDING_REVIEW`）。不用驼峰（Java 枚举常量规范就是全大写），不用短横线（与 Java 标识符不兼容），不用全小写 |
| 2 | **展示文案不进标识符、不进线上值、不进库** | 「公开 / 加载失败 / 本地推理」这类中文**只出现在界面 label 映射**（`frontend/src/constants/labels.ts`）里。后端视图若要给中文，给一个独立的 `label` 字段，**不要**把它当取值 |
| 3 | **不引 i18n 框架** | 当前单语种，label 映射表足够。真要多语种时再说（`07 §8.8`「要了再说」的口径） |

**为什么改掉旧口径**：旧做法是「库、代码、契约三处同一个中文字面量，少一层映射少一处对不上」。
它确实省了一层映射，代价是**把展示文案变成了机器码** —— 于是中文写进了 Java 标识符（`public enum UserStatus { 正常, 停用 }`）、写进了 JSON、写进了库约束。这不符合开发规范，也无法国际化、无法排序、对工具链不友好。
新口径把「机器码」与「展示文案」分开：**机器码稳定、可比较、可排序；文案随时可改而不影响契约与数据**。

---

## 二、全量映射表

### 2.1 后端枚举（Java 常量 = 序列化值 = 库存值）

| 枚举 | 旧 | **新** |
|---|---|---|
| `ClassificationLevel` 密级 | 公开 / 内部 / 秘密 / 机密 | `PUBLIC` / `INTERNAL` / `SECRET` / `CONFIDENTIAL` |
| `DataScope` 数据范围 | own / shared / all | `OWN` / `SHARED` / `ALL` |
| `Visibility` 资源可见性 | 常量大写，**值**是小写 | 常量与值统一 `PRIVATE` / `SHARED` / `PUBLIC`（**删掉 `VisibilityConverter` 的一层映射**） |
| `SubjectKind` 共享主体 | user / role / org / group / link | `USER` / `ROLE` / `ORG` / `GROUP` / `LINK` |
| `UserStatus` 用户状态 | 正常 / 停用 / 待审核 | `ACTIVE` / `DISABLED` / `PENDING_REVIEW` |
| `ModelStatus` 模型状态 | 未加载 / 加载中 / 已加载 / 加载失败 | `NOT_LOADED` / `LOADING` / `LOADED` / `LOAD_FAILED` |
| `Supplier` 供应商 | 本地推理 / 外部API | `LOCAL_INFERENCE` / `EXTERNAL_API` |
| `ModelKind` 模型种类 | chat / embedding | `CHAT` / `EMBEDDING` |
| `ThinkingMode` 思考三态 | NONE / TOGGLEABLE / ALWAYS_ON | **不变**（已是规范） |
| `ToolsMode` 工具三态 | UNSUPPORTED / SUPPORTED / PARALLEL | **不变** |
| `ErrorCode` 错误码 | `ACCOUNT_LOCKED(1001,…)` | **不变**（常量已是大写；`code` 是数字，不是枚举取值） |

> ★ `ClassificationLevel` 的**声明顺序即密级高低**（`ordinal` 递增 = 越敏感），这个语义与命名无关，改名时**不要调整顺序**。

### 2.4 补录：审计时发现的表外 union（规则同 2.2，一并换码）

> 第一轮落地时发现规格漏了这些（它们同样是**被 `===` 比较 / 出现在 JSON 里的取值**）。

| union | 旧 | **新** |

| `WorkflowRecord.status` / `nodeTrail[].status` | 成功 / 失败 | `SUCCEEDED` / `FAILED` |

| `noRefStrategy` | 拒答 / 自由回答 | `REFUSE` / `FREE_ANSWER` |
| `logic`（条件逻辑） | 且 / 或 | `AND` / `OR` |
| `ModelCapability.source` | 探测 / 手工声明 | `PROBED` / `MANUAL` |
| `ChatMessage.role` | user / assistant | `USER` / `ASSISTANT` |
| `ChatMessage.feedback` / `FeedbackItem.type` / `submitMessageFeedback` 的 `type` | up / down | `UP` / `DOWN` |

★ 特别提醒：`role: 'user'`（消息角色）、`source: 'local'`（文档来源）、`key: 'workflow'`（发布检查项的键）
这类**与枚举撞词**的字面量，换码时**不能盲替换** —— 先确认它是不是本表里的枚举取值。

## 三、边界（改哪些、**不改**哪些 —— 这里最容易改出 bug）

| 改 | **不改** |
|---|---|
| 作为**取值**参与比较 / 传输 / 落库的字面量（契约 union、JSON、库列、check 约束、`===` 比较、mock 数据、状态机） | **中文展示文案**：按钮文字（`confirmButtonText: '停用'`）、提示语、label 文案、`label:` 字段 |
| Java 枚举**常量名**及其全部引用点 | **文件名 / 目录名 / 组件名**（`components/nodes/start-node/index.vue` 这类路径不动） |
| 库里**存量数据**的取值（迁移里 `update` 翻译） | **节点实例 id**（`start-1`、`ai-chat-1` 这类图上的节点 id） |
| | **权限点码**（`knowledge:view` 这类 `resource:action`，本来就是英文小写冒号，是另一套词汇） |
| | 错误码的数字与 message 文案 |

★ 一条实用判据：**如果这个字面量被 `===` 比较过、或出现在 JSON/库里，它就是取值，要改；如果它只出现在标签/文案/标题位置，它就是展示，不改。**
两者重合的地方（如 `{{ row.status }}` 直接渲染取值）⇒ **改成查 label 映射**。
