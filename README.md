# 知识助理平台

[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)
[![Status](https://img.shields.io/badge/status-frontend%20ready%20%C2%B7%20backend%20planned-lightgrey.svg)](#现在到哪了)

把**企业文档**变成**可问答的知识服务**的平台。

企业里的知识散在合同、制度、报销规定、供应商资料里。想真正用起来，通常要过三关：

1. **把文档变成可检索的知识** —— 切分、向量化、可治理（哪一段来自哪份文件、处理失败能重试）
2. **把知识 + 模型 + 提示词组装成一个可发布的服务** —— 而不只是搭一个本地 demo
3. **让业务方直接问，并且答案能指回原文** —— 引用不到出处的答案，在企业场景里没法用

本平台把这三件事做成一条链：**知识库 → 应用 → 会话**。在链之上再加一层**编排**，
让「收集 → 检索 → 判断 → 回复」这类多步审查也能配出来，而不只是单轮问答。

---

## 三个核心概念

| 概念 | 是什么 |
|---|---|
| **知识库** | 文档的容器 + 加工管线。上传后自动切分入库，每段保留来源文件与位置，供检索时回引 |
| **应用** | 把模型、知识库、提示词组装成的**可发布问答服务**。分两档：**简单**（提示词约束的单轮问答）与**编排**（画布式多步流程） |
| **会话** | 一次问答。有引用栏、有赞踩、可以生成免登录的公开分享链接 |

**编排**是它跟普通问答系统的分界线：节点有 17 种（AI 对话、知识库检索、条件判断、
语义/数值分支、回复、参数收集、表单收集、图文生成…），在画布上连成流程图后发布。
一条流程里可以用多个模型，也可以在不同分支用不同知识库。

## 给谁用

| 角色 | 关心什么 |
|---|---|
| 知识运营 | 建知识库、导入与治理文档、维护问答对、命中测试 |
| 应用配置 | 建应用、写提示词、挂知识库、调检索参数、编排工作流、发布上线 |
| 普通用户 | 直接问答，看引用，反馈好不好用 |
| 管理员 | 账号、组织、角色权限、模型接入 |

## 现在到哪了

**说得直白些：知识库这条链已经是真后端在跑（上传 → 解析 → 分块 → 向量化，进度来自库）；问答那条链还没有。**

| 部分 | 状态 |
|---|---|
| 前端 | **9 个模块的界面已成工程**；接口契约已冻结 —— 默认跑 mock，`VITE_USE_MOCK=false` 即切真后端，**页面代码一行不动** |
| 设计 | 需求规格（11 册）+ 系统设计（14 册）已成文，**技术选型已全量收口**（逐项见 [`系统设计方案/09`](docs/系统设计方案/09-中间件与-Spring-模块选型.md) §十）、**RAG 的策略 / 落地 / 加工链 / 密级隔离已成册**（[`10`](docs/系统设计方案/10-RAG-检索策略设计.md) · [`11`](docs/系统设计方案/11-RAG的SpringAI落地设计.md) · [`12`](docs/系统设计方案/12-文档加工链设计.md) · [`13`](docs/系统设计方案/13-密级与数据隔离设计.md)） |
| 后端 | **三个域已落地**：身份（登录/刷新/锁定/验证码/权限点）、模型接入（目录探测/启停/向量化端口）、知识库（建库/建档/解析/分块/向量化/分段治理）。**对话 · 编排 · 检索 · 分析看板仍按周推进** |

这是一份**以契约为轴**的工程：先把十一个领域的接口定死（`frontend/src/api/**`），
再照着它做后端 —— 契约漂移由构建期的 `ContractDriftTest` 双向对账兜着。

**所以现在哪些能真用、哪些还不能，要分页看**：知识库、模型管理、系统管理三块是真链路（有一组真栈闸门盯着，
见 [`docs/ROADMAP.md`](docs/ROADMAP.md) §7.1）；对话、应用市场、运营看板等页面**界面在、后端未落地**，
打开就会看到接口 404 —— 那是**按计划欠着**，不是坏了。

路线与验收口径见 [`docs/ROADMAP.md`](docs/ROADMAP.md)。

## 方向

平台的完整形态按四条推进，详见 [`docs/ROADMAP.md`](docs/ROADMAP.md)：

1. **后端** —— 先打通「模型 → 知识库 → 检索 → 问答（流式）→ 应用」这条主链
2. **页面功能** —— 首次引导、公开分享链路、编排的执行状态、空态与失败态
3. **开源工程化** —— CI、容器化、示例数据（仍缺）、[贡献者文档](CONTRIBUTING.md)
4. **编排执行引擎** —— 配置面已经可用，执行引擎是最后一块

技术选型上有一条明确的取舍：**不用商业基座、不用其 CRUD 模板产物**。
界面只依赖宽松开源许可的组件（Element Plus、LogicFlow 等），字体自托管（OFL-1.1）。
