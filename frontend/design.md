# Design — 知识助理平台

本文件是本 App 的**锁定设计系统**。每个页面在改样式之前先读它；页面之间**求同不求异** ——
结构化多样性只发生在组件层面，主题、字体、色、圆角、CTA 语气一律共用。
系统要长，就**改这份文件**（加 `## Variants` 或 `## Per-page allowance`），**不要在页面里局部覆盖**。

生成于 Hallmark（首次运行）。`tokens.css` 是本文件的机器可读镜像，`src/styles/index.css` 是运行时入口。

`modern-minimal` —— 企业平台 / 后台 / B2B / 开发者工具这一档。

## Register — Editorial（★ 第三轮新增）

**Genre 没变，变的是「排印档」（register）。** 使用者 2026-10-16 的原话：
「**我需要一个更现代的设计，并且现在页面的功能还是太紧凑了…现在的设计还是偏向于一个传统的管理平台**」。

**诊断（可核对）**：问题**不在配色**——冷调近白 + 单一钴蓝 + 三字族本身就是现代 SaaS 语汇。
「传统管理平台」的观感来自三处**执行**：

| 成因 | 证据（改造前） |
|---|---|
| ① **全站同构** | 19 个路由只有 3 种骨架：页头 → 说明块 → 过滤框 → 卡片网格/表格 |
| ② **线条密度过高** | `.panel` / `.card` 全是 `1px solid var(--color-rule)`；过滤条也套 panel ⇒ 屏幕上全是闭合矩形 |
| ③ **密度与层级都太平** | 页边距 24 / 区块间距 16 / 卡片内边距 16（**三者几乎相等**）· 字号 12-13-14 是增量不是比率 · 标题 600 对正文 400 只差 200 单位 |

**第三轮的立场 = Editorial 档的核心动作：Hairlines, not card borders（分面用发丝线，不给每个容器套边框）。**

### Editorial 档的六条硬规矩

1. **分面用发丝线，不用盒子。** 内容件（列表项、卡片、KPI 块）**取消盒体**，改用发丝线 + 留白分组；
   只有**面板 / 浮层**（弹窗、抽屉、画布、需要明确边界的功能容器）保留边界，且改用
   `--ring-hairline`（6% 透明度的环）——同一条线的视觉重量降到约 1/4。
2. **留白是内容，且三段必须彼此可辨**：`--band-gap` 64 → `--section-gap` 40 → `--card-pad` / `--grid-gap` 24。
   ★ 判据：**卡片内边距 ≠ 区块间距 ≠ 页内边距**。三者相等就是"模板感"的直接来源。
3. **大字号承担层级，不靠加字号档数**：页面标题 28 · 区块标题 22 · 卡片标题 18 · 正文 15 · 元信息 12。
   字重对比必须 **≥ 300 单位**（正文 400 ⇒ 标题 **700**）—— 400 对 600 只差 200，读起来是"默认设置"。
4. **非对称优先**：页头左偏；主从两栏不等宽（如 `1.6fr / 1fr`）；**窄栏只放正文级微标签**（日期、口径、footnote）。
   ⚠️ **禁止** tag-left / header-right 的两栏 section 头（左边一个编号/标签、右边一个标题）——
   这是 editorial 风格最容易被认出来的模板痕迹。区块头一律**单列竖向堆叠**。
5. **不用 eyebrow。** `01 / 密级`、`02 · 内容` 这类编号/章节标签**默认关闭**。
   只有当内容本身真的有序（步骤、章节）时才用，且**每页上限 1–2 处**。
6. **meta 行走 mono 大写 + `--tracking-meta`（0.12em）**：只用于报头与区块的元信息行（版本 / 环境 / 区间 / 计数）。

### Editorial 档仍受的约束

- **pill 按钮允许**（`--radius-pill` 只给**页面级主行动**；行内按钮仍走 `--radius` 8px）。
  Editorial 禁的是 **pill + 渐变**，不是 pill 本身。
- 禁：纯 `#000` / 纯 `#fff` · 玻璃拟态 · 卡中卡 · 三列等宽"图标在上-标题-两行文案" · 渐变文字 · 投影堆叠 · 滚动入场 · 斜体标题。
- **纸媒语气里没有阴影**：深度靠线、色阶、留白。投影只保留 `--shadow-float` 给浮层。

## Macrostructure family

| 页面类型 | 基线结构 | 允许的变量 |
|---|---|---|
| **应用页**（13 个业务模块 + 外壳内所有页） | **Workbench** —— 标题小而功能性，正文由**发丝线**分区，数据/界面本身是内容。没有营销节奏：没有 hero、没有两端 CTA 条、没有滚动入场。 | 页头（标题 + 元信息行 + 操作区）的三种排布；内容容器（表格 / 看板 / 表单 / 主从双栏）；空态与加载态 |
| **应用外壳**（`_shell`） | **报头 + 双发丝线**（★ 第三轮：Editorial 的 N6/N9 语汇，形态按 12 个目的地的 app 需要调整）—— 60px 通栏、滚动时轻模糊；左 = 字标 + 竖发丝线 + **3 个分组触发**；右 = **meta 行（mono 大写）** + `⌘K` 提示 + 一个主行动 + 用户。**底边是双发丝线**（Editorial 签名）。分组展开为**全宽面板**（带一句话描述），不再是小下拉。**仍不用左侧 rail。** | 面板的排布与描述文案；右侧动作是什么 |
| **沉浸页**（登录、公开问答） | 同上，但**允许用掉本页唯一那一次「深色石墨拍子」**（Cobalt 签名 8） | 深色拍子出现在登录页左栏 / 公开页页头；一页只能有一个 |

**结构禁令**：不许出现居中大标题 hero、不许 `min-height: 100vh` 的居中单句、
不许三列等宽「图标在上-标题-两行文案」的功能格子、不许卡片套卡片、不许每个区块都滚动淡入。

## Theme — Cobalt

一个信号色。冷调工程白纸，靠**发丝线**分面，不靠投影。圆角紧、像用尺子画的。

```css
--color-paper:        oklch(97.4% 0.004 252);   /* 画布底 —— 冷调近白，不是 #fff */
--color-surface:      oklch(99.4% 0.002 252);   /* 卡面 / 浮层 —— 比画布亮一档，不是纯白 */
--color-sunken:       oklch(95.8% 0.005 252);   /* 凹槽：表头、输入框、代码块 */
--color-hover:        oklch(96.8% 0.006 252);   /* 行/项 hover */

--color-rule:         oklch(90.5% 0.008 252);   /* 主发丝线 —— 分面全靠它 */
--color-rule-2:       oklch(94.0% 0.006 252);   /* 内部次分隔线 */
--color-rule-strong:  oklch(85.0% 0.010 252);   /* 输入框边、需要更清楚的界线 */

--color-ink:          oklch(24.0% 0.020 258);   /* 标题 / 主文本。冷炭，不是 #000 */
--color-ink-2:        oklch(38.0% 0.017 257);   /* 正文 */
--color-muted:        oklch(56.0% 0.013 256);   /* 次要说明、标签 */
--color-faint:        oklch(68.0% 0.010 255);   /* 占位符、禁用 */

--color-accent:       oklch(58.0% 0.200 256);   /* 电光钴蓝 —— 唯一信号色 */
--color-accent-hover: oklch(52.0% 0.210 256);
--color-accent-ink:   oklch(99.0% 0.005 256);   /* 压在 accent 上的文字 */
--color-accent-soft:  oklch(96.0% 0.028 256);   /* 选中行底 —— 极浅钴 */
--color-accent-line:  oklch(88.0% 0.055 256);   /* 选中边 */

--color-focus:        oklch(58.0% 0.200 256);   /* 焦点环 = accent */

/* 状态语义 —— 只用于标签、圆点、行内文字，绝不做大面积填充 */
--color-ok:           oklch(55.0% 0.115 158);
--color-warn:         oklch(62.0% 0.130 72);
--color-danger:       oklch(55.0% 0.170 27);

/* 深色石墨拍子 —— 一页只许出现一次 */
--color-graphite:     oklch(22.0% 0.016 260);
--color-graphite-2:   oklch(27.0% 0.018 260);
--color-graphite-ink: oklch(93.0% 0.008 260);
```

**accent 用量上限：任一视口 ≤ 5%。** 只许出现在：选中态左竖条 / 输入焦点环 / 链接 hover 下划线 /
一个主按钮 / 状态点。其余全是 ink-on-cool-white。

**禁**：纯 `#000` / 纯 `#fff` · 灰阶零彩度（每个中性色都带 0.004–0.020 的冷色彩度）·
紫→蓝/青渐变 · 渐变文字 · 毛玻璃（`backdrop-filter` 只许出现在顶栏一处）·
彩色左条 callout · 投影堆叠（深度靠**线**和**色阶**，不靠阴影）。

**与 Element Plus 的关系**：`--el-*` 由 `src/styles/element-plus.css` 单向映射到上面这些令牌。
**页面不许直接写 `--el-*` 或 `--el-color-primary`** —— 那等于绕开这套系统。

## Typography

**2+1 三面封顶**：display + body + mono。第四个字族就是 slop。

```css
--font-display: 'Space Grotesk', var(--font-cjk);
--font-body:    'Geist', var(--font-cjk);
--font-mono:    'JetBrains Mono', ui-monospace, 'SFMono-Regular', Menlo, monospace;
--font-cjk:     'PingFang SC', 'HarmonyOS Sans SC', 'Microsoft YaHei', 'Source Han Sans SC',
                'Noto Sans CJK SC', sans-serif;
```

**中文排印专项纪律（本项目最重要的四条，照搬英文配方会出错）：**

1. **正文字号保底 14px**（`--text-sm`）。当前工程有 18 处 11px、53 处 12px —— 11px 一律抬到 12px，正文一律 14px。中文在 11px 已丢笔画。
2. **行高分两档，不许一刀切。** `--leading-body: 1.75` 给**阅读性文本**（markdown、消息体、说明段落、`.notice`，用全局 `.prose`）—— 汉字是满高字形、没有升降部做缓冲，行距不够就是一片黑。`--leading-ui: 1.6` 给**界面**（表单、表格、标签、按钮、密集列表）—— 那类内容是"扫"不是"读"。★ 一刀切 1.75 是错的：实测把编排画布的 9 个节点卡各撑到 1641px 总高，整图超出可视区、2 个节点被切掉。
3. **中文标题字距必须为 0。** 拉丁 display 的 `-0.02em ~ -0.04em` 会让汉字**笔画相撞**。负字距只许加在纯拉丁/数字元素上。
4. **不要合成斜体。** 中文没有真斜体，`font-style: italic` 会得到机械倾斜的糊字。强调一律用**字重 / accent 色 / 下划线**。

**字号阶梯**（★ 第三轮重排：**接近 1.2 的比率**，不再是 3px 一跳的增量）：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--text-2xs` | 12px | 元信息、mono 全大写小标签（中文下限） |
| `--text-xs` | 13px | 密集区：表格单元格、行内注释、读数说明 |
| `--text-sm` | **15px** | **正文 / 界面默认 / 表格**（第三轮 14 → 15） |
| `--text-md` | **18px** | 强调正文、卡片标题、读数（16 → 18） |
| `--text-lg` | **22px** | 区块标题（20 → 22） |
| `--text-xl` | **28px** | 页面标题（24 → 28） |
| `--text-2xl` | **36px** | 品牌字、沉浸页主标题（32 → 36） |
| `--text-3xl` | **44px** | 仅登录页深色拍子（40 → 44） |

★ **14px 这一档整个消失**：表格不再比正文小一号，表格直接吃正文档。
少一档 = 少一处"要不要小一号"的犹豫。★ 正文下限仍是 14px（汉字在 11–12px 已丢笔画），
但**下限不等于该用的值** —— 15px 是这一轮"不紧凑"最有效的一刀，它同时抬起表格、表单、按钮、列表。

**单页最多用 5 档。** 层级不够时用字重和颜色补，不要再加字号。

**字重**：正文 400 一档；标题与正文对比 **≥ 300 单位**（正文 400 ⇒ 标题 **700**）。
★ 第三轮把 display 从 600 抬到 **700**：400 对 600 只差 200 单位，读起来是"默认设置"而不是"设计过的层级"。
display 用 Space Grotesk **700**，正文用 Geist **400**，强调用 Geist **500**。
行高：`--leading-display` 1.08 · `--leading-title` 1.25 · `--leading-ui` 1.6 · `--leading-body` **1.8**（阅读档）。

**两处 outlier 位（mono 只许占这两处）**：① 全大写小标签（页头元信息、表头、状态、kbd 提示），`letter-spacing: 0.08em`；② 数字列 / ID / 版本号 / 接口路径。
**数字列必须 `font-variant-numeric: tabular-nums`。**

**标点**：中文用「」，英文用 “ ”，破折号 ——，省略号 …；不写 `--` 与 `...`。

## Spacing

4pt 刻度，九档，**按角色命名**。页面只许用 `var(--space-*)`，不许写裸数值。

```css
--space-3xs: 2px;   --space-2xs: 4px;   --space-xs: 8px;
--space-sm: 12px;   --space-md: 16px;   --space-lg: 24px;
--space-xl: 40px;   --space-2xl: 64px;  --space-3xl: 96px;
--space-4xl: 144px;  /* 仅沉浸页 */
```

**★ 第三轮：刻度本身不动，改用「角色令牌」决定谁用哪一档。**
页面里一律引用角色令牌，**不许各自去挑 `--space-*`** —— 否则下一个人改节奏要翻 19 个文件。

```css
--page-pad-block:  var(--space-xl);   /* 40px 页内纵向 */
--page-pad-inline: var(--space-xl);   /* 40px 页内横向（≥1600px 提到 --space-2xl） */
--band-gap:        var(--space-2xl);  /* 64px 大带之间：摘要条 → 主体 */
--section-gap:     var(--space-xl);   /* 40px 区块之间 */
--grid-gap:        var(--space-lg);   /* 24px 卡片 / 网格之间 */
--card-pad:        var(--space-lg);   /* 24px 面板与卡片内边距 */
--row-pad-y:       var(--space-sm);   /* 12px 表格行 / 列表行 */
```

**节奏**：同级兄弟用 `gap`，不用成串 `margin`。
★ **判据（可核对）：卡片内边距 ≠ 区块间距 ≠ 页内边距。** 三者相等就是扁平节奏（改造前是 16/16/24）。
三段现在是 **24 / 40 / 40**，外加 64 的大带间距 —— 节奏有"件 / 区 / 带"三级。

**版面度量**：`--content-max: 1560px`（超宽屏内容居中，不再无限拉长）· `--measure: 68ch`（说明文字行长上限）。

## Motion

**只做微交互。应用页零滚动入场**（这是 Cobalt 的立场，也是反模式清单里的点名条目）。

```css
--ease-out:    cubic-bezier(0.16, 1, 0.3, 1);     /* 进入 */
--ease-in:     cubic-bezier(0.7, 0, 0.84, 0);     /* 离开 */
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);    /* 状态切换 */
--dur-micro: 120ms;   /* 按下、勾选、颜色变化 */
--dur-fast:  160ms;   /* ★ 第三轮：浮层开合、输入聚焦、导航切换 */
--dur-short: 220ms;   /* hover、下拉、提示、弹窗 */
--dur-long:  420ms;   /* 抽屉、登录页那一次入场 */
--dur-enter: 400ms;   /* ★ 第三轮：编排式入场（一次性）、读数跳动 */
```

- **只动 `transform` 与 `opacity`。** 不动 `width/height/top/left/margin/padding`。
- 禁用浏览器默认 `ease`、禁用 bounce/overshoot/elastic、禁用视差、禁用无限循环。
- **焦点环瞬间出现，不做过渡**（过渡会让键盘用户在最开始那 200ms 看不到指示）。
- `@media (prefers-reduced-motion: reduce)` 下所有位移塌缩成 ≤150ms 透明度交叉淡入 —— 全工程必须有这一条。

### ★ 第三轮的动效层（使用者的原话：「让登录和页面操作没有那么死板」）

**为什么这时才开**：技能把 **Workbench 列为「默认就该有动效」的原型** ——
数据密集的界面完全静止会读成一张截图。本项目此前**只有登录页那一次 `.rise`**。
但"开动效"必须配一条纪律，否则它立刻变成 slop：

> **每页最多 3 个「编排式原语」。** 编排式 = 有起点/终点、要人读懂的动效
> （入场 / 读数跳动 / 导航切换 / 浮层开合 / 按下）。
> **既有的"悬停换色"不计入** —— 它是状态样式（颜色变化确认"鼠标在这儿"），不是编排。

| 原语 | 落点 | 动什么 | 时长 · 缓动 | 降动效 |
|---|---|---|---|---|
| **按下** | `element-plus.css`（按钮）· `_shell`（导航/菜单项） | `translateY(1px)` | 100ms · `--ease-out` | 150ms（仍按下） |
| **编排式入场** | `index.css` 的 `.enter` | 子项错峰 60ms，`opacity 0→1` + `translateY(8px→0)` | `--dur-enter` · `--ease-out` | 150ms |
| **读数跳动** | `components/CountUp.vue` | **值**从 0 到终值（元素不动） | 400ms · cubic ease-out | **跳过，直接给终值** |
| **导航切换** | `_shell` 的 `<Transition name="route" mode="out-in">` | 交叉淡入 + `translateY(±6px)` | 出场 72ms `--ease-in` / 入场 `--dur-fast` `--ease-out` | 150ms |
| **浮层开合** | `element-plus.css`（弹窗 keyframes / 令牌桥） | 弹窗 `scale(0.96→1)` + 淡入（EP 默认是"从上滑入"，已改） | `--el-transition-duration` = `--dur-short` · `--ease-out` | 150ms |

**逐页预算**：登录 = **3/3**（表单错峰入场 · 按下 · 左侧那片云）；
工作台 = **3/3**（入场 + 读数跳动 + 导航切换）；
模型管理 / 知识库 / 应用管理 / 应用市场 = 3/3（入场 + 导航切换 + 按下）。

### 沉浸页的**自绘拓扑** —— 唯一一处无限循环（有界例外；由 GSAP 的 DrawSVG 驱动）

四次反馈的完整路径（记下来是因为**前三次我都在调参数，而问题在素材**）：

| # | 使用者原话 | 我的处置 | 结果 |
|---|---|---|---|
| 1 | 「让登录有视觉先感受效果」 | CSS 到达 + 20s 呼吸 | 太含蓄 |
| 2 | 「只有打开的一瞬间。像屏保一样一直动，路径按**贝塞尔曲线**」 | 单层沿闭合三次贝塞尔游走（36s） | **「这个动画太丑了」** |
| 3 | 「有没有开源的 vue 动画库，不要自己写。能不能用 gsap」 | **GSAP + 三层同源素材差分漂移** | **「只是一个云 太丑了」** |
| 4 | 「你看一下 GSAP 有没有好的 demo 效果，**只是一个云 太丑了**」 | **换成自绘拓扑**（本版） | — |

**★ 第 4 次的诊断（解释前三次为什么都没治本）**：1–3 版换的都是**运动方式**
（平移 → 沿路径 → 多层差分），但**素材始终是那片 `blob` 位图**。
一片云不管怎么动，都是"一张贴图在动" —— 它与这个产品的语言**没有任何关系**。
⇒ 该换的是**素材**，不是运动。

**换成了什么**：用 GSAP 官方 demo [Draw a path](https://demos.gsap.com/demo/draw-a-path)
的那一招（`gsap.from('.draw-me', { duration: 1, drawSVG: 0 })` —— `DrawSVGPlugin` 通过
`stroke-dashoffset` / `stroke-dasharray` 揭示描边），画一张**知识图谱**：

| 阶段 | 做什么 | 时长 |
|---|---|---|
| ① 画线 | **83 条边**按**每轮重洗的顺序**错峰生长 | 8s |
| ② 节点亮起 | 每个节点在**它第一条边画到**的那一刻出现 ⇒ 顺序是**可读的**（"图在被搭起来"） | 随 ① |
| ③ 信号游走 | **24 条**随机边上有钴蓝亮段扫过，**扫到末端时终点节点打一下点**（缩放 2.4× + 淡出） | 22s |
| ④ 溶解 | 线从末端往回抹掉、节点随机散掉 | 4.5s |
| ↻ | `onComplete` **重新洗牌**起新的一轮 ⇒ 永不重复 | — |

**★ 为什么这次是对的**：① **隐喻正确** —— 这是知识助理平台，图谱就是它的内容本身；
② **视觉语言同源** —— 本系统的底色是"工程图纸 + 发丝线 + 蓝图网格"（页头那条 hatch 就是网格），
方形节点也接上既有的"状态方点"语言；③ **动画即形态** —— 不是"一个东西在位移"，而是**线在生长**。

**★ 一处刻意偏离"只动 transform / opacity"**：`drawSVG` 驱动的是 `stroke-dashoffset`，
属于**绘制层**而不是合成层。这里接受它，因为**"线条生长"这个效果没有 transform 等价物**。
边界：路径数有限（18 条）、单轮时长长、降动效下**完全不动** ⇒ 这是**有理由的例外**，不是疏忽。

**★ 铺满整栏 + 文字区挖空**（使用者：「动画范围，可以是那个墨蓝色背景的全部吧，现在的动效范围太小」）：
节点从「下半部一条带」扩到**整栏**（44 个 / 83 条边，x 22–650、y 37–863），但**四处文字区被挖空**
（品牌字 / 标题 / 标语 / 页脚）—— 所以线条不会压在字上，标题落在一个干净的空档里。
构图不是手搓的：**8×10 抖动网格 + 文字区排除 + 每点接 3 个近邻 + 10 条跨栏主干**
（近邻 40–190px；只连近邻会让整栏读成「若干座孤岛」），再由脚本统计度数
（最小 1 / 最大 7 / 平均 3.8）。**密度是使用者第二次点名要的**
（「密度高一点，现在线段还是少了」）⇒ 边数 38 → 83，节点 31 → 44。

**★ 线色调过两次，两次都是「打开截图看」换来的**：
① 只有 18 条边、集中在一角时，`--color-graphite-rule`（33%）**太淡** ⇒ 几条线看不见、节点像孤立的方块
⇒ 改成 `muted`(66%) 与 `rule` 的中点 ≈ 50%。
② 铺满整栏后线条密度上升，同一条线「够不够清楚」的要求随之下降 —— 判据是
**密度 ↑ ⇒ 单线对比度可以 ↓**：38 条时维持 ≈51%，**83 条时降到 ≈48%**
（`muted` 55% → 45%）。目的不是变淡，而是让**整体重量**不变、纹理更细。

**★ 开销实测（这条推翻了我自己的预期）**：`drawSVG` 动的是 `stroke-dashoffset`，属于**绘制层**
而不是合成层，我原以为铺满整栏后会掉帧。实测（headless Chrome，1600 × 900）：
**83 条线时：动效开 60.3 fps / 最差一帧 17.0 ms />32ms 的帧 0 帧**，
与**降动效静止时（60.5 fps）几乎无差**（38 条时是 60.2 fps —— **密度翻倍，读数没动**）。
⇒ 结论：**这个量级下，「绘制层动画」的代价量不出来**。
⚠️ 边界仍要写清：这是 headless Chrome 的读数，**低端真机没有测**；真要上低端设备，先降边数。

**★ 颜色：动态、随机，但只用「蓝族五档」**（使用者：「线段的颜色最好是**动态颜色**的，
不要纯白，节点也随机颜色」）

- **色阶定义在 `tokens.css`**：`--art-wire-1..5` = 236 青蓝 → 256 钴蓝 → 280 蓝紫，L/C 逐档变化。
  放那里的两个硬理由：① 它是**调色板的唯一住所**（`check_design.py` 把页面里的 `oklch(` / `rgb(` /
  `#hex` 一律判为「行内颜色字面量」）；② 该文件在 `FROZEN` 里（立法者不参与评分）。
- **每轮重新随机分配**（与「生长顺序」一起洗）⇒ 画面在变的不只是位置，还有颜色。
- **连续色相漂移**：整组**一次** `hue-rotate`（±9°、48s 往返）。为什么不给 127 个元素逐个补间
  `stroke`：那是 127 处颜色插值 + 每帧重绘；一次分组 filter 就把同一件事做完
  （而且中性灰不受 `hue-rotate` 影响 —— 变的是彩色那部分）。
- **枢纽节点取 accent**（度数 ≥ 5），其余随机 —— 让颜色**带一点含义**，不是纯彩纸屑。
- **节点改成实心方点**：本系统「状态方点」的语言本来就是实心 5×5 方块（空心框读起来像复选框），
  而且 1px 的空心彩边几乎看不出颜色 —— 实心才真的「有颜色」。
- **★ 不用 `--color-ok / warn / danger` 当装饰色**：它们在本系统里**有语义**
  （绿 = 正常 / 琥珀 = 警告 / 红 = 危险）。拿它们画装饰线，等于让「绿」不再意味着健康。
- **★ 记账：这是对「accent ≤ 5% 视口」的一次显式取舍。** `--color-accent` 本身**不进随机池**
  （只给信号与枢纽节点），但整块面板的**彩度**确实比只有灰线时高得多。
  判据：色阶与 accent 同属一个色相族（236–280）、且沉浸页装饰层本来就有一片蓝色位图底光 ⇒
  它读起来是「同一个蓝世界」，不是「第二个强调色」。
  **要回到严格灰度只需把 `--art-wire-*` 五档换成石墨中性色 —— 代码一行不改（颜色全部走令牌）。**

**★★ 一处被探针抓到的静默失败（本轮的真正收获，值得单独记）**：
`gsap.utils.random(数组, true)` 的第二个参数含义是「**返回一个可复用函数**」，不是「从数组里取值」。
我把它插进字符串 ⇒ 生成 `var(function(){…})` ⇒ 自定义属性是垃圾值 ⇒ `var()` 解析失败 ⇒
**静默回退到兜底色：83 条线全是同一个颜色，不报错、不 console 红、页面看不出「坏了」**。
探针是靠「数不同颜色的**种数**」（读到 1 种）才抓到它的。
⇒ 这就是本工程头号病 `silent-failure` 的标准形态：**界面看起来「就是那样」，而规格里写的是另一回事。**
⇒ 判据：**凡是"随机/变化"的东西，验证必须量「取值种数」，而不是「有没有设上」。**

**★ 降动效：把图画完就停**（不空着、也不动 —— 静态的图本身也是一张好看的图）。
实测（`prefers-reduced-motion: reduce`，指向构建产物的临时静态门禁）：
无开关时 **83/83 条线已画满 · 44/44 节点可见 · 无缩放** ⇒ 一张**完整且静止**的图；
`?motion=on` 时线正在画（此刻 41/83）、节点有缩放、首条线带 `stroke-dasharray: 101.831px, 0.1px`。

根目录 `THIRD-PARTY-NOTICES.md` 的 `gsap` 一节 ——
**全仓库唯一一条依赖方可以单方面修改条款的许可**。

### ★★ 方法论盲区：动效探针默认把被测环境改了

**这是本轮最值得记的一条。** 使用者报"没有动画"时，我先跑探针 —— 探针说"动画在跑"，
而使用者看到的确实没有。原因在探针自己身上：

> **Playwright 的 `reduced_motion` 默认值是 `no-preference`**（不是"不覆盖"）。
> 实测：不传该参数与显式传 `no-preference`，页面里 `matchMedia('(prefers-reduced-motion: reduce)').matches`
> **都是 `false`**。⇒ 我此前所有"动效验证通过"，**全部是在一个把系统设置强制关掉的环境里测的**，
> 结构性上不可能发现"使用者的环境报 reduce"。

**两条处置**：
1. 动效类探针**必须显式声明** `reduced_motion="no-preference"` 或 `"reduce"`，并在结论里写明测的是哪一种。
   **想要系统真值就别用 Playwright** —— 它的默认值会覆盖掉你要测的东西。
2. **"看不看得见"要用像素回答，不能用"属性在不在动"回答**：
   `transform` 在变 ≠ 人眼看得见（第一版 1.1 px/s 也一直在变）。正解是**截多帧比像素**：
   整页平均/峰值差，可辨阈值约 1/255、明显约 3/255。本轮实测峰值 **34/255**。
   ★ 同族教训：探针里 `m[1][0]` 取的是**字符串第 0 个字符**而不是第 1 个数字，
   于是 scale 恒读成 1 —— 又一次"**读数先怀疑探针**"（本工程已有先例）。

### ★ 显式动效开关（`?motion=on` / `?motion=off`）

**为什么有它**（实测得来，不是预置功能）：使用者的机器上系统级"减少动效"是开着的 ——
`matchMedia('(prefers-reduced-motion: reduce)').matches` 实测 `true`，
与注册表 `MinAnimate = 0` 一致 —— 于是全工程动效被正确折叠，而**他本人明确要求看得到动效**。
⇒ 口径：**系统默认仍是默认，使用者的显式要求优先。**

| 访问方式 | `<html data-motion>` | 效果 |
|---|---|---|
| 什么都不带 | 无 | **尊重系统**（reduce 环境下只保留"不透明度"这一路） |
| `?motion=on` | `on` | 完整动效（位移 + 缩放 + 不透明度），并**持久化**到本机 localStorage |
| `?motion=off` | 无 | 回到尊重系统，并持久化 |

**实现**：`src/lib/motion.ts` 在 `main.ts` **挂载前**跑一次 ——
读**整串 URL**（hash 路由下 `?motion=on` 放在 `#` 前或后都认得）·
写 `localStorage['aip.motion']` · 投影成 `<html data-motion="on">`。

★ 这条开关落在**两套动效体系**上，各自的处理方式不同（这是最容易搞混的一处）：

| 动效体系 | 谁在用 | 降动效/开关落在哪 |
|---|---|---|
| **CSS 动效** | `.enter` 错峰入场 · 导航切换 · 按下 · EP 浮层/弹窗 | `src/styles/index.css` 的全局塌缩规则带 `:root:not([data-motion='on'])` 守卫 —— **只此一处** |
| **JS 动效（GSAP）** | 登录页那张**自绘拓扑** | `pages/login/useSlateTopology.ts` 的 `motionAllowed()` —— **CSS 规则对它无效**（GSAP 走 rAF + 内联样式） |

★ 也就是说：**登录页那些装饰层一行 CSS 动画都没有**（`.slate-halo` 完全静止，
`.slate-topology` 的生长/扫过/溶解全部由 GSAP 编排）—— 降动效完全由 JS 判。
**两边都写=两个主人，必有一边静默失效**（本轮真实踩过：全局 CSS 塌缩规则
曾把 CSS 侧的降动效分支吃成「150ms 跳一下」，而 `animationName` 那一栏看起来完全正常）。

★ 这是全工程**唯一**一处允许绕过降动效的地方，且必须由使用者显式开启；
没有那个属性时，行为与加它之前**完全一致**。
★ 实测（上下文固定 `prefers-reduced-motion: reduce`；**证据看内联样式里有没有位移**，
换 GSAP 之后 `animationName` 不再是有效读数）：

| 用例 | data-motion | 证据（自绘拓扑） |
|---|---|---|
| 无开关（默认） | 无 | 线色 **5 种** · 节点色 **6 种** · **83/83 条线已画满** · `filter: none` ⇒ **有色、不动** |
| `?motion=on` | `on` | 同样的颜色 + 线**正在画**（46/83）+ `hue-rotate(-8.6deg → -6.92deg)` ⇒ **在漂移** |
| `?motion=off` | 无 | 回到「有色、不动」 |

★ 这张表里最要紧的一条：**颜色与动效是两件事** —— 颜色在两种模式下**都在**
（它是静态属性，降动效不该把它也拿走），被移除的只有「漂移/生长」这些**运动**。

★ 证据形态随实现变过两次（`animationName` → 内联 `opacity/transform` → 线的绘制状态）。
**读数要跟着实现改**，否则那张表会变成"看着像绿的"的历史残留。

★ **记账口径（写在这里以备质疑）**：那片光场算**一个**动效原语（"登录页第一眼的光"），
尽管它由三层 × (到达 + 漂移 + 呼吸) 构成 —— 它们在**同一个视觉对象**上是同一件连续的事。
不这么记，登录页会记成 10 个原语、远远越过上限。
**这条口径可以被质疑**（"三层难道不是三个原语？"）：我采用的判据是
**"人看到的是一个东西还是一个列表"** —— 光场是一片的，卡片网格是一列。

**★ 明确"不加"的（每一条都是被点名的 AI 味）**：
hover 抬升卡片（与既有禁令一致）· bounce / overshoot / elastic · 滚动淡入（应用页立场不变）·
视差 · 光标跟手 · 彩色辉光 · `transition: all` · 动画化 `width/height/top/left` ·
庆祝式成功提示 · 无限循环（加载器与骨架屏除外）· 把动效加在**布局属性**上。

**两条实现纪律（都由一次真实风险换来的）**：
1. `.enter` 用 `animation-fill-mode: both`，**不预设 `opacity: 0`** ——
   预设的写法在"动画没跑起来"时会把内容**永久藏掉**。
   判据：删掉 `@keyframes enter`，内容仍然可见。
2. `CountUp` 对 `null`（没测到）渲染「—」且**不跳** ——
   把"没数据"演成"从 0 涨到 0"是拿动效撒谎。AT 只播报**终值**一次（跳动中的数字 `aria-hidden`）。

**★ 兜底的读数（新增断言）**：`check_theme.py` § 4.5 —— 降动效下 `.topbar` 的过渡必须塌到 ≤150ms，
**且**先证明它平时 >150ms（否则那条断言恒真）。
反证：把兜底规则的 `150ms` 故意改成 `220ms` → 闸门报 **11/12 exit 1**，
失败项正是「降动效下 .topbar 过渡塌到 ≤150ms」。

**★ 读数跳动的实测**（探针，不是断言）：登录落地（数据在）时抓到序列
`600.4 → 693.2 → 721.1 → 723`，终值 `723 / 262 / 91.5% / 7`（百分比格式保住），
AT 播报区拿到的也是终值。
⚠️ 工作台**刷新后**读数全是「—」，`CountUp` 此时**不跳**（按"不拿动效撒谎"的纪律）——
那张截图里的四个破折号是**另一个真缺陷**，见下节，不是动效没生效。

## Microinteractions stance

- **静默成功**（silent success）：用户能看见结果的动作不弹成功提示。提示只留给失败、异步且结果不可见、以及用户需要留痕的确认。
- 可逆动作（删一行）**不做确认弹窗**，做乐观删除 + 可撤销；不可逆动作才用弹窗。
- 提示的 hover 延迟 800ms、focus 延迟 0ms（意图不同，时序不同）。
- 必须给**全部 8 态**样式：default · hover · `:focus-visible` · `:active` · disabled · loading · error · success。

## Signature-move completion

**增补理由（实测）。** `themes/cobalt.md` 给了 8 个签名动作，首轮实现只落地了 1 / 2 / 3 / 6 与半个 7 ——
**全部属于「克制」那一半**；签名 **4（代码/回执即主角）、5（真能用的 ⌘K）、8（每页一条深色带）**
三项未落地，而这三项恰是**焦点与戏剧性**。结果就是"读数正确但无焦点"：发丝线 + 空白 = 一份文档。

**判据：克制不带焦点，等于没有设计。** 本节把 4 / 5 / 8 定为**系统的一部分**，不是可选的装饰件。

## 仪器面板（签名 4 + 8）

**组件族 `InstrumentCard`**：深色石墨（`--color-graphite`）、mono 标签、右上角状态胶囊、等宽读数行。
它回答「**这台机器此刻在做什么**」，是 Cobalt 的焦点元素。

| 约束 | 值 |
|---|---|
| 每视口上限 | **一个**（按视口算，不按页算） |
| 数据来源 | **必须是真实数据**（现成契约：`analyticsApi` / `ingestionApi` / `assistantsApi`）。**不许编数字** —— 编造指标是本系统最严重的违规 |
| 圆角 | 10px（比卡片松一档 —— Cobalt 对代码/回执件的口径） |
| 阴影 | 只许一条 `0 1px 2px` 的极轻抬起，不许堆叠 |
| 字体 | 标签 mono 大写 `0.06em`；读数 mono + `tabular-nums`；说明用 body |
| 状态胶囊 | 只许四态：`OK` / `RUNNING` / `WARN` / `ERROR`，配 `--color-ok/warn/danger/accent` |

**签名 8 的放宽**：深色石墨带从「仅沉浸页」放宽到「**每页至多一条**」，且**用途固定**为
「机器回执 / 展示时刻」。它**不能**退化成装饰性色条 —— 判据是：**去掉它，页面会失去一个读数**；
若去掉后什么都没少，它就不该在。

**各页落点（逐条可核，全部真实数据）**：工作台 → 近 7 天回执（`analyticsApi.getQualityMetrics`）·
知识库详情 → 入库管线阶段读数（`ingestionApi.getIngestionProgress` 的服务端真实进度）·
应用概览 → 发布状态 + 凭证 · 编排画布 → 已有（节点图本身即面板，**豁免**）· 登录 / 公开页 → 已有。

## 命令面板（签名 5）

**⌘K / Ctrl+K 打开，真的能用。** 这是本系统唯一的「行为像开发工具」的签名交互。

- 能力：**跳页**（13 个模块，**按权限过滤、与顶栏菜单同源**）+ **动作**（建知识库 / 建应用 / 开始问答）。
- 规约：`role="dialog"` · `aria-modal="true"` · 焦点管理（开聚焦输入框、关归还触发元素）·
  Esc 与点遮罩关闭 · ↑↓ 选择 · 输入过滤 · `prefers-reduced-motion` 下无位移。
- 顶栏右侧有一个**带框的 ⌘K 提示**（mono 大写），点它等同按键。

## Art layer —— 有界的水彩许可

**这是对 `themes/cobalt.md:62`（no texture/pattern）与 `imagery-kit.md:144`（modern-minimal 不用装饰图像）
的一次显式、有界的覆盖**，由使用者要求。**开许可的方式是限定表面，不是放开风格。**

**允许的表面（穷举，别处一律不许）**：

| 表面 | 形态 | 上限 |
|---|---|---|
| 沉浸页（登录 / 公开问答） | 一片有机色场，**偏向一侧**（禁居中）+ 一个具名前景层；
★ 第三轮修订：色场可为**一组同源分层**，前景层可以是**线条构成的结构图**（见 § Motion 的自绘拓扑） | 每页色场 **1 组** + 前景 **1 个** |
| ★ **页头通栏底**（每个应用页都有） | **蓝图细网（hatch）**，`multiply` | 每页 **1** 条带，不超 `--art-opacity-hatch` |
| 空态 | **mono 线稿示意图** + 一片极浅色场 | 每个空态 1 组 |
| ★ **石墨带内** | **蓝图细网（hatch）**，`screen` | 每带 **1** 片，不超 `--art-opacity-screen` |
| 沉浸页的深色栏内 | 极细颗粒（grain） | 1 片，不超 `--art-opacity-grain` |

**★ 增补理由（使用者反馈：「界面中没有看到资源效果，还是很呆板」）**
首版把艺术许可只开在**登录页 / 空态 / 公开页**上 —— 那三个表面**在正常使用路径上几乎遇不到**，
于是"把应用翻一遍看不到任何艺术"。这不是执行问题，是**许可范围与可见路径不重合**。

**修法不是"到处加图"**，而是把表面补到**每页都有**的那个东西上 —— **页头**。
判据：**页头是「表面」不是「正文」** —— 正文仍然零装饰，数据仍然零干扰。

★ 为什么页头用 **hatch（可平铺的网格）而不是 wash（色场）**：
`imagery-kit.md` 的反模式里写着 **"不要给多个区块铺同一片水彩 —— 它是 section 强调，不是全局处理"**。
而**页头每页都有一个** ⇒ 铺 wash 就等于做了全局处理。**网格是纹理，本来就允许平铺**；
色场是强调，只许出现在沉浸页与空态。**这条区分是本表里最容易搞错的一处。**

**禁止**：应用页正文区出现任何位图 · 同页两片 wash · 三个以上素材叠一页 · 居中衬在文字后 ·
**暖色**（暖色是 Coral 的地盘；本系统只有冷调 250–258）· 任何需要外网的 URL。

**形状纪律（防"抽象渐变盖标题"这个头号 AI 默认）**：色场必须**偏向一侧**、**比你以为的更大**、
**不透明度有上限**（浅色纸 0.6 / 深色底 screen 0.35 / 颗粒 0.15）。

**★ 两条用量纪律（实测得来，对所有色场用法都成立）：**

1. **`wash-cool-01` 的蓝压在素材自己的四角**（实测左/右缘 alpha 118/255、上 94、下 108）
   ⇒ **任何 `cover` 直铺都会露出一块硬边矩形**（看起来像贴了张纸，不像色场）。
   正解 = **`mask` 强制四边归零**（`radial-gradient(closest-side, black 50%, transparent 100%)`）
   **+ 放大对准素材的能量团**（实测 `background-size: 340% auto` 才把它对进 mask 核心；
   不放大则羽化会把蓝全吃掉，`tint = 0`，等于没放）。
   判据（客观）：**紧贴元素边界内外的相邻像素差应为 0** —— 这条量法能直接抓到硬边。
2. **`--art-opacity-*` 是元素 `opacity` 的上限，不等于视觉强度的上限。**
   放大对准之后，`--art-opacity-wash` 满档实测峰值色差 **118/765** —— 蓝会把压在上面的线稿盖住；
   半档 60/765 才是"衬得住又不抢"的档位。**先量像素再顶上限**，不要因为"上限是 0.6"就写 0.6。

**产出机制（离线、可复现、自托管）**：
- 源 `src/assets/art/src/*.svg` —— **手工 SVG**（`feTurbulence` 做颗粒、径向与网格渐变做色场）。它是可版本化、可令牌化的真源。
- 成品 `src/assets/art/*.png` —— 用**已装的 Playwright** 栅格化（`page.screenshot({type:'png'})`）。
  **不走任何外部 CDN**，符合本项目"自托管 + 离线冒烟"的纪律。
- 体积：单文件 ≤ 200 KB，全目录 ≤ 1.2 MB。重生成：`python tools/rasterize_art.py`（幂等）。

## Per-page allowance

- **应用页正文**：**禁止装饰位图**，功能本身承担页面 —— 但**每页至多一条仪器面板**（见上），
  它算功能件，不算装饰。
- **空态**：**允许**「mono 线稿示意图 + 极浅色场」，但**排法有硬要求** ——
  必须是**两栏（图偏一侧、字在另一侧）**，**不许居中大图**。
  理由：「一张大插画居中 + 标题 + 按钮」是这个品类里最标准的 AI 味空态；
  偏一侧的两栏排法既避开了它，又让示意图去解释**机制**（这张图在说什么流程）而不是卖萌。
  仍**不许**插画、不许彩色、不许把示意图拉满宽。
- **沉浸页**（登录、公开问答）：允许一次深色石墨拍子 + 一片偏向一侧的有机色场。
- **编排画布**：仍是唯一豁免「零装饰」的区域（节点卡、连线、网格背景都是功能件）。
- **任何页面**：accent ≤ 5% · 单页 ≤ 5 档字号 · 无滚动入场 · 深度靠线与色阶，不靠投影。

### ⚠️ 本轮发现的既有缺陷（**不属设计范围，需按 R60 开 Issue**）

**工作台刷新后读数与仪器面板全部丢失，且完全静默。**

| 步骤 | `.stat` 四个读数 |
|---|---|
| 登录后停在原地 900ms | `723 / 262 / 91.5% / 7` ✓ |
| 再等 4 秒 | 仍然正确 ✓ ⇒ **不是时序** |
| `goto('#/')` 之后 | **全部「—」** ✗ |
| **硬刷新**之后 | **仍然全部「—」** ✗（仪器面板也消失、常用应用变空） |

**已排除**：① 不是认证丢失（刷新后顶栏正常显示「管理员」）；② 不是时序（多等 4s 不恢复）；
③ 不是被 catch 吞掉（注入 `unhandledrejection` 监听后**零 rejection**，且 `src/api/analytics.ts` 无 `catch`）。
页面**没有任何错误文案、没有重试入口、控制台零报错**。

**最可疑的机制（待验证，不作为结论）**：`frontend/README.md` 记着
「**401 时静默刷新一次，并发请求排队等同一个刷新**」—— 刷新后挂载时若首个请求在会话就绪前发出，
这条"静默"路径正好会把失败吃掉，与观测到的三个特征（无错、无数据、会话正常）全部吻合。

**与本轮的关系**：**不是我改出来的**（我没碰数据层）。但第三轮把读数从 22px 抬到 28px/700
⇒ 这个"没有数据"的状态被放大成四个巨大的破折号，**看起来像页面坏了**。
⇒ 设计意图是"让数字承担视觉重量"，前提是**数据真的在**；数据断了必须能看见。

**建议的判据（可核对）**：刷新工作台后 `.stat` 里**不得出现「—」**（真实数据下）；
读取失败时页面必须给出可行动的原因 + 重试入口 —— 与 `docs/ROADMAP.md §二` 的
**A2「状态真实性：刷新页面不重置」**同源，而那条目前只验了分段页（`check_segmentation_e2e.py`），
**没有验工作台**。

★ **三条命令层的坑（会把绿读成红、或把旧产物读成新读数）**：
1. `python smoke_test.py 2>&1 \| Select-Object` 会把静态服务器的**访问日志（走 stderr）**并进管道，
   PowerShell 因此返回 **exit 1** —— 而脚本自己打印的是「34/34 通过」。**用 `2>$null` 才是真读数。**
2. `verify_features.py` / `smoke_test.py` / `verify_permissions.py` **自带静态服务器、服务的是 `dist/`**
   ⇒ 它们验的是**构建产物**、不碰使用者在跑的 dev server；而 `check_theme` / `shot_sweep` / `check_canvas`
   要 dev server 的 URL。**先 `build:mock` 再跑前者**，否则验的是旧产物。
3. 这些脚本的默认端口（4205 / 4209 / 4210）落在 Windows 动态排除区（3788–4586）⇒ 本机跑要
   `AIP_GATE_PORT` 覆盖（如 `14205`）。
4. ★ **DOM 闸门不要与 `vite build` 并发跑**（2026-10-16 记，**证据不足但值得防**）：
   一次 `smoke_test` 在 `npm run build:mock` 同时进行时报 `exit 1`，而**单独重跑是 34/34、exit 0**；
   那次我把输出截断了、**没留住失败项名字**，所以"并发导致"只是最可能的解释，**不是结论**。
   ⇒ 纪律：**重活（构建）与浏览器闸门串行跑**（本工程已有同族判据：
   "后端重活别让两路同时跑 —— 会抢 Testcontainers/端口"）。
   ★ 更要紧的一条：**看到 `exit 1` 先问"刚才还有什么在跑"，再问"哪一行改坏了"** ——
     否则会把偶发当成回归，去改一处本来没坏的代码。
5. ★ **自己搭临时静态门禁时，必须带 SPA 回退**（2026-10-16，一次自坑换来）：
   `check_theme.py` 打开的是**路径式** URL（`{BASE}/login`）—— Vite dev server 有 history
   fallback，而 `python -m http.server` **没有** ⇒ `/login` 直接 404、页面根本没加载，
   于是它在 `input[autocomplete="username"]` 上超时、报 `exit 1`。
   **第一反应是"我改坏了吗"，实际是脚手架缺回退**（补上回退后立刻 12/12）。
   ⇒ 判据：**用临时门禁替代用户的 dev server 时，先把 dev server 的隐含能力补上**
   （history fallback），否则红的是脚手架、你却在查产品。
6. ★ **`log_message` 要覆盖在「处理器类」上，不是「服务器类」上**：
   `SimpleHTTPRequestHandler` 的访问日志是**处理器**打的，挂到 `ThreadingTCPServer` 上不生效
   （我挂错过一次，日志照样打）。
7. ★ **PowerShell 在原生命令往 stderr 写任何东西时会报 `[exit code: 1]`** ——
   即使那个进程 `exit 0`（同族记录已有：`smoke_test.py` 的访问日志）。
   ⇒ **看 python 的退出码要看 `$LASTEXITCODE`，不要看 pwsh 这一层的红**；两者一致地红才是真的红。
